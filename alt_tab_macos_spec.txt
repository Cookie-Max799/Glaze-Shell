ТЗ: ПЕРЕКЛЮЧАТЕЛЬ ПРИЛОЖЕНИЙ ALT+TAB В СТИЛЕ macOS (Cmd+Tab)
=====================================================================

ЦЕЛЬ
Реализовать переключатель приложений по Alt+Tab, который ведёт себя как Cmd+Tab на macOS. Модификатор Cmd заменён на Alt. Это НЕ стандартный оконный Alt+Tab из Windows: в списке одна иконка на приложение, а не на окно. К переключателю добавляются анимации в стиле macOS, (опционально) режим обзора окон в стиле Mission Control, а также описание рабочего стола macOS: иконки, Dock, Launchpad, Spaces и анимации запуска приложений.

Общие ориентиры:
- Порядок приложений: MRU (most recently used).
- Панель: горизонтальная полоса с иконками одного размера.
- Выход из режима: отпускание Alt активирует выбранное приложение.
- Анимации: короткие, физичные, прерываемые.


---------------------------------------------------------------------
1. КОНТЕКСТ: КАК УСТРОЕНО НА macOS
---------------------------------------------------------------------
На macOS нет единого аналога Windows Alt+Tab. Есть три механизма:
1. Cmd+Tab переключает ПРИЛОЖЕНИЯ (панель с иконками). Это основной образец для реализации.
2. Cmd+` переключает ОКНА текущего приложения без визуального списка.
3. Mission Control / Exposé показывает все окна одновременно как миниатюры разного размера (см. раздел 9, опционально).


---------------------------------------------------------------------
2. МОДЕЛЬ ДАННЫХ
---------------------------------------------------------------------
- Список приложений: одна запись на процесс/приложение (окна группируются по приложению). Поля записи: иконка, название, список окон, флаги hidden, minimized, hasWindows.
- Порядок MRU: последнее активное приложение первое, предыдущее второе и т.д.
- MRU обновляется при КАЖДОЙ смене фокуса в системе, а не только через переключатель. Нужно подписаться на события активации окон/приложений ОС.
- Приложения без окон (фоновые, в трее) остаются в списке, если они запущены и пользовательские. Системные службы фильтруются.


---------------------------------------------------------------------
3. ЖИЗНЕННЫЙ ЦИКЛ (STATE MACHINE)
---------------------------------------------------------------------
Состояния: Idle -> Switching -> Idle.

ВХОД: нажатие Alt+Tab в состоянии Idle.
- Снять снимок списка MRU.
- Выделить ВТОРОЙ элемент (индекс 1), потому что первый это текущее приложение.
- Показать панель. Допустима задержка показа 100-150 мс, чтобы быстрое "нажал и отпустил" не мигало панелью, а просто переключало.

ПОКА ALT ЗАЖАТ (Switching):
  Tab            - выделение на следующий элемент (с зацикливанием)
  Shift+Tab      - выделение на предыдущий
  Стрелки <- ->  - сдвиг выделения влево/вправо
  Q              - завершить выделенное приложение (послать close всем окнам), убрать из списка, выделение остаётся рядом
  H              - скрыть/свернуть выделенное приложение, остаётся в списке
  Стрелка вниз или 1 - показать окна выделенного приложения (раскрыть список/превью его окон)
  Esc            - отмена, ничего не переключать, вернуться в Idle
  Клик по иконке - активировать это приложение и закрыть панель
  Hover          - подсветить иконку (без активации)

ВЫХОД: отпускание Alt.
- Активировать выделенное приложение (на передний план, передать фокус).
- Обновить MRU: активированное приложение становится первым.
- Скрыть панель, вернуться в Idle.


---------------------------------------------------------------------
4. ПРАВИЛА АКТИВАЦИИ
---------------------------------------------------------------------
- У приложения есть окна: поднять ПОСЛЕДНЕЕ АКТИВНОЕ окно этого приложения.
- Окон нет (приложение живёт в трее): активировать приложение, окна не создавать.
- Приложение свёрнуто: по умолчанию НЕ восстанавливать автоматически. Если при отпускании Alt зажат Shift (аналог Option на macOS), окно восстанавливается. Либо настройка "восстанавливать свёрнутые" (по умолчанию выключена).
- Приложение скрыто (через H): при активации показать снова.
- Быстрое нажатие и отпускание (до появления панели) = переключение между двумя последними приложениями (MRU[0] <-> MRU[1]).


---------------------------------------------------------------------
5. ПАНЕЛЬ (UI)
---------------------------------------------------------------------
- Горизонтальная полоса с иконками ОДНОГО размера, по центру экрана, поверх всех окон, без рамки.
- Фон полупрозрачный с блюром (acrylic/mica на Windows, blur на Linux-композиторах).
- Выделенный элемент: скруглённая подсветка за иконкой.
- Название выделенного приложения под или над панелью.
- Если иконок слишком много для ширины экрана: сначала уменьшить размер иконок до минимального, затем перенос на второй ряд.
- Опционально: индикатор (точка под иконкой) у приложений без окон.
- Панель показывается на экране, где сейчас курсор или активное окно.
- Панель НЕ должна забирать фокус у активного окна до подтверждения выбора.


---------------------------------------------------------------------
6. ПЕРЕКЛЮЧЕНИЕ ОКОН ВНУТРИ ПРИЛОЖЕНИЯ (аналог Cmd+`)
---------------------------------------------------------------------
- Alt+` циклически переключает окна текущего приложения (MRU внутри приложения), без панели или с лёгкой индикацией.
- Важно: на русской раскладке клавиша ` даёт другой символ (ё), а Alt+Shift может переключать язык. Привязываться к СКАН-КОДУ клавиши, а не к символу. Дать возможность переназначить.


---------------------------------------------------------------------
7. ПЕРЕХВАТ КЛАВИШ И СИСТЕМНЫЕ НЮАНСЫ
---------------------------------------------------------------------
WINDOWS
- Alt+Tab зарезервирован системой. Нужен низкоуровневый хук (SetWindowsHookEx, WH_KEYBOARD_LL), который ПОДАВЛЯЕТ событие и не отдаёт его системному переключателю.
- Список окон: EnumWindows, фильтр по WS_EX_TOOLWINDOW, видимости, owner.
- Активация: SetForegroundWindow (учесть ограничения на передачу фокуса).
- Иконки: GetClassLongPtr(GCLP_HICON), SHGetFileInfo или иконка из exe.

LINUX X11
- Глобальный grab через XGrabKey. Список окон через EWMH (_NET_CLIENT_LIST_STACKING, _NET_ACTIVE_WINDOW).

LINUX WAYLAND
- Глобальный перехват зависит от композитора. Обычно реализуется как расширение/плагин самого окружения (GNOME Shell, KWin).

macOS (если агент делает это на Mac)
- Список окон: CGWindowListCopyWindowInfo (kCGWindowBounds, kCGWindowOwnerName, kCGWindowLayer, kCGWindowNumber), фильтр kCGWindowLayer == 0.
- Миниатюры: ScreenCaptureKit (SCScreenshotManager, SCContentFilter), нужно разрешение Screen Recording.
- Управление окнами: Accessibility API (AXUIElement, kAXRaiseAction), нужно разрешение Accessibility.
- Перехват клавиш: CGEventTap (Input Monitoring или Accessibility).
- Отрисовка: borderless NSPanel уровня .screenSaver или .popUpMenu, NSVisualEffectView для блюра.
- MRU: NSWorkspace.didActivateApplicationNotification и AX-наблюдатели смены фокуса окон.

ОБЩЕЕ
- Отпускание Alt нужно отслеживать ГЛОБАЛЬНО, а не только пока панель в фокусе.


---------------------------------------------------------------------
8. АНИМАЦИИ (В СТИЛЕ macOS)
---------------------------------------------------------------------
8.0 ОБЩИЕ ПРИНЦИПЫ
- Короткие и физичные: 150-350 мс. Дольше воспринимается как лаг.
- Кривые: ease-out для появления (быстрый старт, мягкая остановка), ease-in для исчезновения, spring (пружина с лёгким перелётом) для "живых" элементов.
- Анимировать только transform (scale, translate) и opacity. Не анимировать размер/layout: дорого и даёт рывки. Цель 60 fps (на 120 Гц дисплеях тоже 120).
- Анимации ПРЕРЫВАЕМЫЕ: если пользователь нажал клавишу посреди анимации, она плавно перенаправляется к новому состоянию из текущего положения, без прыжков и без доигрывания.
- Учитывать системную настройку Reduce Motion: заменить масштаб и перемещение на простой fade (~100 мс) или мгновенное переключение.

8.1 ПОЯВЛЕНИЕ И ИСЧЕЗНОВЕНИЕ ПАНЕЛИ
- Показ: opacity 0->1 и scale 0.96->1.0, ~120-150 мс, ease-out.
- Скрытие: opacity 1->0, ~80-100 мс, ease-in. Активация приложения НЕ ждёт конца анимации.
- Быстрое "нажал и отпустил": панель не показывается вообще.
- Иконки внутри панели не анимируются при появлении, появляется вся панель целиком.

8.2 ВЫДЕЛЕНИЕ ВНУТРИ ПАНЕЛИ
- Подсветка не телепортируется, а СКОЛЬЗИТ от старой иконки к новой за ~100-150 мс (ease-in-out или лёгкая пружина).
- Hover: мгновенная подсветка или fade ~60 мс.
- Иконка выделенного приложения может слегка увеличиваться (scale 1.0->1.05).
- Закрытие приложения клавишей Q: иконка уменьшается и исчезает (scale->0.5, opacity->0, ~150 мс), остальные иконки плавно сдвигаются, закрывая пустое место.
- Скрытие клавишей H: короткое мигание или затемнение иконки.

8.3 ОТКРЫТИЕ ОКНА (появление нового окна)
- Окно появляется в центре своей финальной позиции: scale 0.9-0.95 -> 1.0, opacity 0 -> 1.
- Длительность ~200-250 мс, ease-out (допустима пружина с минимальным перелётом).
- Тень появляется вместе с окном.
- Для диалогов и листов (sheets): выезд сверху вниз из заголовка родительского окна.

8.4 ЗАКРЫТИЕ ОКНА
- Обратная анимация: scale 1.0 -> 0.9-0.95, opacity 1 -> 0.
- ~150-200 мс, ease-in (закрытие быстрее открытия).

8.5 СВОРАЧИВАНИЕ И РАЗВОРАЧИВАНИЕ
- Свернуть: окно уменьшается и "втягивается" к иконке на панели задач/в доке.
  * Вариант Scale: простое уменьшение к позиции иконки с fade, ~250-300 мс, ease-in-out.
  * Вариант Genie: окно искривляется в "воронку", сужаясь к иконке (мэш-деформация, нужна GPU-отрисовка), ~400-500 мс.
- Развернуть: обратная траектория, из иконки к исходной позиции и размеру.
- Целевая точка: координаты иконки приложения на панели задач. Если недоступна, использовать нижний центр экрана.

8.6 АКТИВАЦИЯ ПРИЛОЖЕНИЯ ПРИ ВЫХОДЕ ИЗ ПЕРЕКЛЮЧАТЕЛЯ
- Окно выходит на передний план БЕЗ анимации перемещения, как в macOS. Допустима лёгкая анимация затемнения предыдущего окна и появления тени у нового (~100 мс).
- Если приложение было скрыто (H): окно появляется по схеме открытия (8.3) или fade-in 150 мс.
- Если приложение было свёрнуто и при отпускании Alt зажат Shift: анимация разворачивания (8.5).

8.7 ПЕРЕКЛЮЧЕНИЕ ОКОН ВНУТРИ ПРИЛОЖЕНИЯ (Alt+`)
- Без перелёта: окно мгновенно или с коротким crossfade (~100 мс) выходит на передний план.
- Опционально: краткая подсветка рамки активируемого окна (~200 мс).

8.8 РЕАЛИЗАЦИЯ И ОГРАНИЧЕНИЯ
Анимировать ЧУЖИЕ окна напрямую обычно нельзя: ОС и сторонние приложения не отдают контроль над их отрисовкой. Стандартный приём:
  1. Сделать снимок окна (screenshot/thumbnail).
  2. Создать собственное безрамочное прозрачное окно-оверлей с этим снимком в тех же координатах.
  3. Анимировать оверлей (scale, opacity, перемещение).
  4. В конце анимации убрать оверлей, а настоящее окно показать/скрыть мгновенно.

Технологии:
- Windows: оверлей на Direct2D/Composition API или WPF/WinUI со Storyboard. Снимки: PrintWindow, Windows.Graphics.Capture, DWM thumbnails (DwmRegisterThumbnail). Системные анимации окон отключать для своих окон через DwmSetWindowAttribute (DWMWA_TRANSITIONS_FORCEDISABLED), чтобы не накладывались.
- Linux: оверлей через композитор (X11 + compositor) либо реализация как расширение композитора (GNOME Shell, KWin), где анимациями окон можно управлять напрямую.
- Кроссплатформенно: оверлей-окно с CSS transitions или Web Animations API (transform, opacity, will-change: transform) в Electron; QPropertyAnimation и QEasingCurve в Qt.
Для СВОЕЙ панели анимации реализуются нативно без проблем. Сложность только с анимацией чужих окон.

8.9 СВОДНАЯ ТАБЛИЦА АНИМАЦИЙ
  Элемент                  | Свойства                     | Время       | Кривая
  -------------------------|------------------------------|-------------|------------------
  Показ панели             | opacity, scale 0.96->1       | 120-150 мс  | ease-out
  Скрытие панели           | opacity                      | 80-100 мс   | ease-in
  Перемещение выделения    | translate                    | 100-150 мс  | ease-in-out/пружина
  Удаление иконки (Q)      | scale, opacity, сдвиг соседей| 150 мс      | ease-in
  Открытие окна            | scale 0.92->1, opacity       | 200-250 мс  | ease-out
  Закрытие окна            | scale 1->0.92, opacity       | 150-200 мс  | ease-in
  Сворачивание (Scale)     | translate+scale к иконке     | 250-300 мс  | ease-in-out
  Сворачивание (Genie)     | мэш-деформация               | 400-500 мс  | ease-in-out
  Reduce Motion            | только opacity               | ~100 мс     | linear


---------------------------------------------------------------------
9. ОПЦИОНАЛЬНО: РЕЖИМ ОБЗОРА ОКОН (аналог Mission Control)
---------------------------------------------------------------------
Отдельный режим (например Alt+Space или жест/горячая клавиша), показывающий ВСЕ окна одновременно как миниатюры разного размера.

ВХОДНЫЕ ДАННЫЕ
Набор окон: у каждого frame (x, y, w, h), заголовок, иконка приложения. Область раскладки bounds = экран минус отступы (меню-бар, панель задач, поля).

ЦЕЛИ РАСКЛАДКИ
- Сохранять ПРОПОРЦИИ каждого окна, без растяжения.
- Не масштабировать выше 1.0: маленькие окна остаются в натуральном размере, большие уменьшаются.
- Окна НЕ пересекаются, между ними зазор ~20-40 px.
- Относительное расположение примерно соответствует реальному (окно слева сверху остаётся слева сверху) для сохранения пространственной памяти.
- Равномерное заполнение области без больших пустот и перекосов.

АЛГОРИТМ (близок к "natural layout" в GNOME/KDE)
  1. Отсортировать окна по положению (сначала по Y-центру, потом по X-центру).
  2. Подобрать число рядов r так, чтобы общий масштаб был максимальным. Распределить окна по рядам, ориентируясь на Y.
  3. Внутри ряда отсортировать по X.
  4. Для каждого ряда: высота ряда = max высота окон (после масштабирования), ширина = сумма ширин + зазоры.
  5. Найти единый коэффициент s (<= 1), при котором все ряды помещаются в bounds по ширине и высоте.
  6. Отцентрировать каждый ряд по горизонтали, весь блок по вертикали. Окна внутри ряда выровнять по центру ряда.
  7. Итоговый targetFrame каждого окна = масштабированный размер в вычисленной позиции.
Упрощённая альтернатива: итеративное отталкивание перекрывающихся окон от исходных позиций с последующим масштабированием до влезания в экран.

ИНТЕРФЕЙС
- Под каждой миниатюрой подпись (иконка и название приложения/окна).
- Hover подсвечивает окно (рамка или лёгкое увеличение).
- Клик выбирает окно и закрывает режим.
- Крестик закрытия появляется при hover в углу миниатюры.
- Фон слегка затемняется и размывается, обои остаются видны.

АНИМАЦИЯ
- Окна плавно перелетают из исходного frame в targetFrame (~0.25-0.4 с, ease-in-out).
- При выходе обратная анимация: к исходному положению или (для выбранного окна) оно выезжает на передний план.
- Окна, которые не выбраны, возвращаются на прежние места.

ГРАНИЧНЫЕ СЛУЧАИ
- Одно окно: по центру, масштаб <= 1.
- Очень много окон: масштаб падает, минимальная ширина миниатюры ограничена, иначе добавляются ряды.
- Несколько мониторов: раскладка считается отдельно для каждого экрана.
- Окна с экстремальными пропорциями (очень узкие/широкие): ограничить макс. высоту и ширину миниатюры.
- Свёрнутые окна: отдельный ряд или в доке.
- Полноэкранные окна живут в собственных Spaces и не входят в общую раскладку.


---------------------------------------------------------------------
10. ГРАНИЧНЫЕ СЛУЧАИ ПЕРЕКЛЮЧАТЕЛЯ
---------------------------------------------------------------------
- В списке одно приложение: Alt+Tab ничего не делает или показывает панель с одним элементом без смены.
- Выбранное приложение закрылось, пока панель открыта: убрать из списка, сместить выделение.
- Появилось новое приложение во время переключения: не менять снимок списка до выхода.
- Alt отпущен до появления панели: просто переключиться на MRU[1].
- Несколько мониторов: панель на одном мониторе, список приложений общий для всех.
- Приложения с повышенными правами (например UAC на Windows): окна могут быть недоступны для активации, предусмотреть обработку отказа.
- Приложение не отвечает при попытке закрытия (Q): не блокировать панель, показать индикатор или принудительно завершать только по явному действию пользователя.


---------------------------------------------------------------------
11. РАБОЧИЙ СТОЛ macOS: РАСПОЛОЖЕНИЕ ПРИЛОЖЕНИЙ И ЕГО УСТРОЙСТВО
---------------------------------------------------------------------
В macOS "рабочий стол" это несколько связанных слоёв. Агент должен различать их и не смешивать.

11.0 СЛОИ ЭКРАНА (снизу вверх)
  1. Обои (wallpaper), на весь экран, на каждом Space могут быть свои.
  2. Иконки рабочего стола (Desktop): ФАЙЛЫ, папки, диски. Это не приложения.
  3. Окна приложений (с тенями, в порядке стека).
  4. Dock (панель с приложениями), поверх окон, кроме полноэкранных.
  5. Меню-бар сверху: меню активного приложения слева, системные индикаторы справа.
  6. Оверлеи: Mission Control, Launchpad, переключатель Cmd+Tab, уведомления.

11.1 ИКОНКИ РАБОЧЕГО СТОЛА
- Размещаются по невидимой СЕТКЕ (grid). Режим "Привязка к сетке" (Snap to Grid) выравнивает иконку к ближайшей ячейке при перетаскивании.
- Порядок по умолчанию: колонки начинаются в ПРАВОМ ВЕРХНЕМ углу и заполняются сверху вниз, затем следующая колонка левее. Диски и тома показываются в правом верхнем углу.
- Иконка: картинка (обычно 64 px) + подпись под ней, до двух строк, с усечением посередине ("длинное_на...ние.txt").
- Выделение: клик подсвечивает иконку и подпись (подпись в цветной капсуле); выделение рамкой (rubber band) мышью по пустому месту.
- Перетаскивание: полупрозрачная копия иконки следует за курсором; при сбросе иконка ПЛАВНО докатывается в ближайшую свободную ячейку сетки (~150-200 мс). Если ячейка занята, ищется ближайшая свободная.
- Двойной клик открывает; Return запускает переименование; Cmd+O открывает.
- Сортировка и упорядочивание: по имени, типу, дате, размеру, цвету метки; "Очистить" (Clean Up) выравнивает по сетке.
- Stacks (Стопки): файлы автоматически группируются в стопки по типу или дате; клик по стопке раскрывает её веером/списком иконок с анимацией (~200-250 мс, ease-out).
- Приложения на рабочем столе МОЖНО держать (как ярлыки), но основное место приложений это Dock и Launchpad.
- Клик по обоям на Sonoma и новее может "показать рабочий стол" (убрать окна в стороны); отдельная настройка.
- Раскладка иконок хранится отдельно для каждого экрана и запоминается (позиция по сетке, не в пикселях).

11.2 DOCK (ГЛАВНАЯ ПАНЕЛЬ ПРИЛОЖЕНИЙ)
Расположение: низ экрана по умолчанию (можно слева/справа), по центру, полупрозрачная "стеклянная" полоса со скруглениями и блюром.

Структура слева направо:
  [ закреплённые приложения | запущенные незакреплённые ]  |разделитель|  [ недавние приложения (опц.) | папки (Загрузки) | свёрнутые окна | Корзина ]

- Левая часть: приложения (Finder всегда первый). Порядок меняется перетаскиванием; остальные иконки РАЗДВИГАЮТСЯ, освобождая место (~200-300 мс).
- Запущенное приложение отмечено ТОЧКОЙ под иконкой (можно отключить).
- Правая часть: папки, свёрнутые окна (миниатюры окон, а не иконки приложений) и Корзина (всегда последняя).
- Увеличение (Magnification): при наведении иконка под курсором растёт до 1.5-2x, соседние увеличиваются по плавной кривой (гауссиана/косинус): чем дальше от курсора, тем меньше. Эффект "волны". Иконки растут вверх, панель на самом деле не меняет высоту, а увеличенные иконки выходят за её границы.
- Подпись: при наведении над иконкой появляется плашка с названием.
- Контекстное меню (правый клик/долгое нажатие): список окон приложения, "Параметры" (Оставить в Dock, Открывать при входе), "Показать в Finder", "Завершить".
- Значки (Badges): красный кружок с числом на углу иконки (уведомления).
- Автоскрытие: Dock уезжает за край экрана и выезжает при подведении курсора к краю (задержка ~0.2-0.5 с).
- Удаление иконки: вытащить за пределы Dock и отпустить, появляется облачко дыма ("poof"), остальные иконки сдвигаются.
- Нажатие на иконку: запускает приложение, если не запущено; активирует, если запущено; показывает все окна при долгом нажатии/App Exposé.

11.3 LAUNCHPAD (СЕТКА ВСЕХ ПРИЛОЖЕНИЙ)
- Полноэкранный оверлей с размытым фоном (обои видны сквозь блюр).
- Сетка иконок (по умолчанию 7 колонок x 5 рядов) с делением на СТРАНИЦЫ; внизу точки-индикаторы страниц.
- Перелистывание: свайп двумя пальцами, стрелки, Cmd+цифры; анимация сдвига страницы ~250-300 мс с инерцией.
- Папки: перетаскивание одной иконки на другую создаёт папку; клик по папке раскрывает её по центру с увеличением.
- Поиск вверху: фильтрует сетку в реальном времени.
- Режим редактирования: долгое нажатие/удержание Option, иконки ДРОЖАТ (jiggle: поворот ±2° с разной фазой, ~0.15-0.2 с цикл), появляется крестик удаления у приложений из App Store.
- Закрытие: Esc, клик по пустому месту, жест "щипок наружу".

11.4 SPACES (ВИРТУАЛЬНЫЕ РАБОЧИЕ СТОЛЫ)
- Несколько рабочих столов (Desktop 1, 2, 3...). На каждом свой набор окон и свои обои (по желанию).
- Полноэкранное приложение создаёт ОТДЕЛЬНЫЙ Space и располагается в нём один (рядом с обычными столами, справа).
- Переключение: Ctrl+<- / Ctrl+->, свайп тремя/четырьмя пальцами, Ctrl+цифра.
- Полоса Spaces в Mission Control сверху показывает миниатюры всех столов; "+" добавляет новый, перетаскивание окна на миниатюру переносит окно.
- Привязка приложения к Space: Dock -> Параметры -> Назначить (Все рабочие столы / Этот рабочий стол / Нет).
- Приложение с окнами на нескольких Spaces: при активации через Cmd+Tab macOS переключает на Space с его окном (настраивается).
- Dock и меню-бар присутствуют на всех Spaces; в полноэкранном режиме скрыты и выезжают по подведению курсора.

11.5 РАСПОЛОЖЕНИЕ И ПОВЕДЕНИЕ ОКОН НА СТОЛЕ
- Новое окно появляется в последней запомненной позиции приложения; новое окно того же приложения КАСКАДОМ со смещением ~22-25 px вправо-вниз от предыдущего. Если окно не помещается, оно возвращается в видимую область.
- Окна не могут быть полностью унесены за пределы экрана: заголовок всегда остаётся достижимым (минимум несколько десятков px видимой полосы заголовка).
- Активное окно: яркие кнопки (красная/жёлтая/зелёная), глубокая тень. Неактивные: серые кнопки, лёгкая тень.
- Зелёная кнопка: полноэкранный режим (новый Space) или "Плитка" (Tile) в половину экрана рядом с другим окном.
- Привязка (Snap): перетаскивание к краям/углам показывает подсветку и раскладывает окно в половину/четверть экрана (Sequoia и новее).
- Stage Manager (опционально): активное окно по центру, остальные группами-миниатюрами в стопке слева, клик по группе меняет центральное окно.
- Окно можно перетаскивать за заголовок и за любую "пустую" область интерфейса; подсвечивается при наведении на край для изменения размера.

11.6 АНИМАЦИИ РАБОЧЕГО СТОЛА И ЗАПУСКА ПРИЛОЖЕНИЙ
Общие принципы те же, что в разделе 8: transform и opacity, короткие времена, прерываемость, Reduce Motion.

А) Запуск приложения из Dock
  1. Иконка ПОДПРЫГИВАЕТ (bounce): плавно вверх на ~высоту иконки и обратно, несколько раз (обычно до 2-3 прыжков), пока приложение запускается. Остановка, как только приложение готово. Кривая: подскок как у падающего мяча, ease-out вверх и ease-in вниз, ~0.5-0.7 с на прыжок.
  2. Под иконкой появляется точка запущенного приложения (fade-in ~150 мс).
  3. Окно приложения открывается: scale 0.92-0.95 -> 1.0 и opacity 0 -> 1, ~200-250 мс, ease-out, с тенью; без перелёта из Dock (на macOS окно не вылетает из Dock при запуске, это отличие от минимизации).
  4. Меню-бар сменяется на меню приложения (мгновенно или с коротким fade ~100 мс).
  5. Если приложение долго запускается, bounce продолжается, затем плавно останавливается.

Б) Запуск из Launchpad
  1. Выбранная иконка слегка увеличивается и подсвечивается.
  2. Launchpad "растворяется": остальные иконки и фон fade out + лёгкое увеличение сетки (scale 1.0 -> 1.1) ~200-250 мс, ease-in.
  3. Одновременно начинается bounce иконки в Dock и открытие окна (см. А).

В) Открытие папки/файла двойным кликом на рабочем столе или в Finder
  1. Иконка слегка подсвечивается.
  2. Окно Finder или окно приложения "вырастает" ИЗ позиции иконки: от размера иконки к финальному размеру окна, scale + translate, ~250-350 мс, ease-out (так же работает Quick Look по пробелу: увеличение из иконки и обратное сжатие при закрытии).
  3. При закрытии окно сжимается обратно к позиции иконки (если она видима), ~200-250 мс, ease-in.

Г) Dock: увеличение при наведении
  - Иконки масштабируются с плавной кривой по расстоянию до курсора; обновление на каждый кадр движения курсора, без задержки.
  - При уходе курсора иконки плавно возвращаются к размеру 1.0 за ~150-200 мс, ease-out.

Д) Dock: добавление, удаление, перестановка
  - Перетаскиваемая иконка следует за курсором, соседние иконки раздвигаются/сдвигаются на ~200-300 мс, ease-in-out.
  - Удаление: "poof" (облачко, ~300-400 мс, scale + fade спрайт-анимацией) и сдвиг соседей.
  - Новое запущенное незакреплённое приложение: иконка плавно ВЫРАСТАЕТ в правой части левой секции (width 0 -> полный размер, ~250 мс), соседи раздвигаются.
  - Завершение незакреплённого приложения: иконка сжимается по ширине до нуля, ~200-250 мс.

Е) Dock: автоскрытие
  - Выезд и уезд за край экрана: translate, ~200-250 мс, ease-in-out. Появление при подведении курсора после небольшой задержки.

Ж) Сворачивание окна и разворачивание (см. 8.5)
  - Окно втягивается в миниатюру в правой секции Dock (Genie или Scale). Миниатюра окна в Dock появляется в конце анимации и сжимается/расширяется по ширине.

З) Переключение Spaces
  - Весь экран (обои, окна) СКОЛЬЗИТ по горизонтали на ширину экрана, ~300-400 мс, ease-in-out. Dock и меню-бар остаются на месте.
  - Лёгкая параллакс-разница между обоями и окнами допустима.
  - Жест следует за пальцами (интерактивная анимация), при отпускании доводится с инерцией.

И) Полноэкранный режим
  - Окно увеличивается до размеров всего экрана, ~400-500 мс, ease-in-out; меню-бар и Dock уезжают за край.
  - Одновременно создаётся новый Space; рабочий стол позади "сдвигается" влево.
  - Выход: обратная анимация к прежнему размеру и позиции.

К) Иконки рабочего стола
  - Выделение: мгновенное, подсветка подписи в капсуле; hover без анимации.
  - Перетаскивание: поднимающаяся тень и полупрозрачность, сброс с плавным докатыванием к сетке ~150-200 мс.
  - Раскрытие Stack: иконки выезжают из стопки веером/списком, ~200-250 мс, ease-out, с небольшим смещением по задержке (stagger ~15-25 мс между иконками).

Л) Launchpad: страницы и редактирование
  - Переключение страниц: translate по X, ~250-300 мс, инерция и "резинка" на краях.
  - Jiggle: непрерывное покачивание, у каждой иконки своя фаза.
  - Раскрытие папки: иконка-папка увеличивается и фон затемняется, ~200-250 мс, ease-out; закрытие обратное.

М) Уведомления и бейджи
  - Dock-иконка прыгает при требовании внимания (критическое уведомление): прыжки повторяются до активации приложения.
  - Бейдж на иконке: появление scale 0 -> 1 с лёгким перелётом, ~150-200 мс.

Сводная таблица:
  Элемент                          | Анимация                          | Время        | Кривая
  ---------------------------------|-----------------------------------|--------------|------------------
  Запуск из Dock (иконка)          | bounce 2-3 прыжка                 | пока грузится| ease-out/in
  Открытие окна приложения         | scale 0.92->1, opacity            | 200-250 мс   | ease-out
  Окно из иконки (двойной клик)    | scale+translate из позиции иконки | 250-350 мс   | ease-out
  Закрытие в иконку                | обратное сжатие                   | 200-250 мс   | ease-in
  Dock magnification               | scale 1->1.5-2, плавная кривая    | покадрово    | гауссиана/косинус
  Возврат размера Dock             | scale -> 1                        | 150-200 мс   | ease-out
  Перестановка иконок Dock         | translate соседей                 | 200-300 мс   | ease-in-out
  Удаление иконки Dock             | poof + сдвиг                      | 300-400 мс   | -
  Автоскрытие Dock                 | translate                         | 200-250 мс   | ease-in-out
  Launchpad показ/скрытие          | opacity, scale 1.1<->1            | 200-250 мс   | ease-out/in
  Переключение Space               | translate X по ширине экрана      | 300-400 мс   | ease-in-out
  Полноэкранный режим              | scale к размеру экрана            | 400-500 мс   | ease-in-out
  Stack раскрытие                  | веер, stagger 15-25 мс            | 200-250 мс   | ease-out
  Докат иконки к сетке             | translate                         | 150-200 мс   | ease-out

11.7 РЕАЛИЗАЦИЯ
МОДЕЛЬ ДАННЫХ
  - Space { id, wallpaper, windows[] }
  - DesktopItem { id, path, gridCell(col,row), screenId }
  - DockItem { id, appId, pinned, running, badge, section(apps|others), index }
  - LaunchpadItem { appId | folderId, page, index }
Состояние Dock собирать из ДВУХ источников: закреплённые (хранятся в настройках) и запущенные (из списка процессов). Объединять по appId.

WINDOWS
  - Иконки рабочего стола: окно Progman -> SHELLDLL_DefView -> SysListView32; можно читать/позиционировать через LVM_* сообщения или реализовать собственный слой. Для собственных обоев/иконок за окнами используют окно WorkerW.
  - Dock-подобная панель: собственное окно AppBar (SHAppBarMessage) или topmost-окно, которому резервируется рабочая область.
  - Виртуальные рабочие столы: интерфейсы IVirtualDesktopManager / IVirtualDesktopManagerInternal (недокументированные части меняются между версиями Windows, нужна осторожность), либо реализовать "Spaces" собственными скрытыми группами окон.
  - Launchpad: собственное полноэкранное borderless-окно с блюром (acrylic) и сеткой иконок из меню Пуск (чтение .lnk и UWP манифестов).

LINUX
  - Рабочие столы: EWMH (_NET_NUMBER_OF_DESKTOPS, _NET_CURRENT_DESKTOP, _NET_WM_DESKTOP). Dock: окно с _NET_WM_WINDOW_TYPE_DOCK и _NET_WM_STRUT_PARTIAL. На Wayland через layer-shell (wlr-layer-shell) или расширение композитора.
  - Иконки приложений: .desktop-файлы и тема иконок (freedesktop).

КРОССПЛАТФОРМЕННО
  - Все анимации выше реализуются на transform/opacity в своём слое: Dock, Launchpad и обзор делаются как собственные окна с GPU-композицией.
  - Анимации ЧУЖИХ окон только через снимок и оверлей (см. 8.8).

ГРАНИЧНЫЕ СЛУЧАИ
  - Много приложений в Dock: иконки автоматически уменьшаются, чтобы поместиться; magnification учитывает минимальный размер.
  - Закреплённое приложение удалено с диска: иконка с вопросительным знаком, клик ничего не запускает.
  - Приложение не запускается: bounce прекращается через таймаут, иконка возвращается в обычное состояние, показывается ошибка.
  - Несколько мониторов: свой Dock/панель на каждом или только на основном (настройка); иконки рабочего стола и Spaces у каждого монитора свои.
  - Смена разрешения или отключение монитора: пересчитать сетку иконок, перенести окна и иконки в видимую область.
  - Нехватка места на сетке рабочего стола: добавлять новые колонки левее, не накладывать иконки.


---------------------------------------------------------------------
12. КРИТЕРИИ ГОТОВНОСТИ
---------------------------------------------------------------------
1. Alt+Tab (быстрое нажатие) переключает на предыдущее приложение без мигания панели.
2. Alt+Tab с удержанием показывает панель, первое выделение на втором элементе MRU.
3. Tab / Shift+Tab / стрелки / Q / H / Esc / клик / hover работают по таблице раздела 3.
4. Отпускание Alt активирует выделенное приложение и обновляет MRU.
5. Системный Alt+Tab не срабатывает одновременно с нашим.
6. Анимации соответствуют разделу 8, прерываются корректно и уважают Reduce Motion.
7. Нет кражи фокуса панелью, нет "залипания" режима, если Alt отпущен вне нашего окна.
8. Работа на нескольких мониторах и с русской раскладкой проверена.
9. (Опционально) Режим обзора окон по разделу 9 раскладывает окна без пересечений с сохранением пропорций.
10. Рабочий стол (раздел 11): иконки встают по сетке, Dock корректно показывает закреплённые и запущенные приложения, magnification плавный, Launchpad и Spaces работают по описанию.
11. Анимации запуска (bounce, открытие окна, окно из иконки, смена Space, полноэкранный режим) соответствуют таблице раздела 11.6 и уважают Reduce Motion.
