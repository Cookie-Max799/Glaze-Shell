# Использование Glaze Shell

Как пользоваться MVP-сборкой Glaze Shell и что она умеет. Сборка и запуск — в [DEVELOPMENT.md](DEVELOPMENT.md), архитектура — в [ARCHITECTURE.md](ARCHITECTURE.md), дизайн-система — в [DESIGN.md](DESIGN.md), стадии — в [ROADMAP.md](ROADMAP.md).

## Возможности

### Обнаружение и запуск приложений

- обнаружение приложений меню «Пуск»: managed-парсер бинарных shortcut-файлов (MS-SHLLINK) с fallback на `IShellLinkW` и shell property store;
- обнаружение MSIX/Store-приложений через AppsFolder (`IShellItemArray`, `PKEY_AppUserModelID`);
- агрегация кандидатов, dedup по launch identity, предупреждения диагностики по каждому источнику;
- запуск: MSIX через `IApplicationActivationManager`, Win32 через `ProcessStartInfo`;
- проверка состояния и закрытие: вежливое закрытие (`CloseMainWindow`, при отсутствии главного окна — `WM_CLOSE` по top-level окнам процесса), а принудительное завершение — отдельное явное действие с подтверждением (`Process.Kill(entireProcessTree: true)` плюс добивание фоновых процессов из несистемного каталога установки); MSIX-пакет определяется по каталогу установки, извлечённому из пути процесса (`WindowsApps\<PackageFullName>`);
- перезапуск: сначала вежливое закрытие, и только если приложение не завершилось — принудительное, после чего запуск; это исключает второй экземпляр рядом с незакрытым первым;
- UI лаунчера: поиск, список с virtualization, статус выполнения с отметкой времени обновления, анимация запуска (круговой индикатор на карточке), клавиатурная навигация (↑/↓, Enter, Space, F5, Esc) с поднесением выбранного элемента к видимой области, яркое выделение выбранной карточки с акцентной полосой, обновление по событиям процессов вместо периодического опроса фоновых процессов.

### Управление окнами

- window manager: перечисление видимых top-level окон, события `WindowOpened`/`WindowClosed`/`ForegroundWindowChanged`/`WindowStateChanged` через `SetWinEventHook`, фокус с best-effort и fallback через `AttachThreadInput`, `ShowWindowAsync` (свернуть/развернуть/восстановить) и вежливое закрытие через `WM_CLOSE`;
- инлайн-панель окон в карточке запущенного приложения: заголовок, состояние, монитор окна, активное окно и кнопки «Фокус/Свернуть/Развернуть/Закрыть»; Win32-окна сопоставляются по пути исполняемого файла, MSIX — по имени семейства пакета;
- фильтрация окон: только видимые, не cloak-нутые (DWM `DWMWA_CLOAKED`) и не tool-windows.

### Мониторы и DPI

- monitor/DPI integration: перечисление мониторов (`EnumDisplayMonitors`), bounds и working area, primary-флаг, scale factor (`GetDpiForMonitor`/`GetDpiForSystem`), refresh rate и ориентация (`EnumDisplaySettingsW`), `MonitorFromWindow`/`MonitorFromPoint`;
- display events: уведомление об изменении конфигурации дисплеев через hidden message window (`WM_DISPLAYCHANGE`, `WM_DEVICECHANGE`/`DBT_DEVNODES_CHANGED`, `WM_SETTINGCHANGE`/`SPI_SETWORKAREA` и `SPI_SETLOGICALDPIOVERRIDE`, `WM_DPICHANGED`) и публикация `DisplayChanged`; отбор сообщений вынесен в `DisplaySignal`, а пачка сигналов объединяется `EventCoalescer` (300 мс) вместо перечисления мониторов на каждое сообщение;
- панель «Мониторы» в футере UI со сводкой, списком устройств (разрешение, DPI, refresh rate, ориентация), схематичной картой мониторов (раскладка `MonitorMapLayout`) с окнами, открытыми на каждом мониторе, и автообновлением по display events;
- пользовательские имена дисплеев: монитор можно переименовать из панели «Мониторы» (диалог «Сохранить»/«Сбросить»/«Отмена»); имя сохраняется в `settings.json` (`monitorNames`) и восстанавливается при следующем запуске. По умолчанию — «MAIN DISPLAY» и «DISPLAY N».

### Системные события

- windows events: единый `ShellEventCoordinator` запускает оконные, дисплейные и процессовые источники и владеет их жизненным циклом; отказ одного источника не блокирует остальные, диагностика возвращается в `ShellEventStatus` и пишется в лог;
- process events: `ProcessEventMonitor` публикует `ProcessStarted`/`ProcessExited` по разнице снимков списка процессов (интервал по умолчанию 1 с); первый снимок базовый, имя и путь читаются только для новых PID, а при отсутствии подписчиков перечисление не выполняется вовсе.

### Рабочее пространство и layout

- desktop layout: полный backend рабочего пространства через `DesktopManager` — вкладки (`CreateTab`/`RemoveTab`/`RenameTab`/`MoveTab`/`ActivateTab`), категории (`CreateCategory`/`RemoveCategory`/`RenameCategory`/`MoveCategory`) и приложения (`AddApplication`/`RemoveApplication`/`MoveApplication`, в том числе перенос между категориями); событие `DesktopChanged`; канонический `Order` нормализуется на каждом уровне, layout нормализуется при установке;
- привязка вкладок к мониторам: `DesktopTab.MonitorId`, `IDesktopManager.AssignTabToMonitor`, снятие привязок к недоступным мониторам при загрузке layout;
- UI-панель вкладок и категорий не подключена: подключение визуального дерева выполняет владелец проекта.

### Темы

- theme system: `ThemeManager` (набор тем, выбор действующей темы, событие `ThemeChanged`), встроенная тема `glaze-default`, загрузка пользовательских тем из `themes/*.json` с проверкой цветов, размеров и безопасности ассетов; тема не может содержать исполняемый код или ссылаться на файлы вне своего каталога;
- переключатель оформления: на странице «Оформление» в настройках доступны режим (Системная/Светлая/Тёмная) и акцентный цвет (шесть вариантов плюс «по умолчанию»). Выбор сразу применяется ко всему интерфейсу — `ThemeApplicator` переключает светлую/тёмную палитру стандартных контролов и перекрашивает токены-кисти на месте, без перезагрузки XAML; режим «Системная» следует системной настройке `AppsUseLightTheme`. Выбор сохраняется в `settings.json` (`themeMode`, `accentId`) и восстанавливается при запуске. Движок меняет только интерфейс Glaze Shell и не изменяет настройки Windows;
- пользовательские темы (`themes/*.json`) к UI пока не подключены: применяется встроенная светлая/тёмная палитра и акцент.

### Настройки

- кнопка «Настройки» в главном окне открывает отдельное окно настроек (I1, базовый слайс). Слева — список страниц, сверху — поиск по настройкам, справа — сами настройки страницы. Окно создаётся лениво и переиспользуется;
- страницы: «Оформление», «Dock», «Верхняя панель», «Проводник», «Доступность», «Восстановление», «О программе». Каждая страница описана декларативно (`SettingsCatalog`), поэтому набор страниц задаётся кодом, а не разметкой окна;
- значения применяются сразу после переключения, сохраняются в `settings.json` и восстанавливаются при следующем запуске. Кнопка «Сбросить страницу» возвращает значения по умолчанию только для открытой страницы;
- ограничения базового слайса: общего сброса всех настроек приложения нет. Автозапуск при входе в систему, сворачивание в трей, восстановление раскладки и выбор языка пока не реализованы — в модели настроек эти поля есть (`startWithWindows`, `minimizeToTray`, `restoreLastLayout`, `language`), но переключателей в интерфейсе нет, чтобы не показывать неработающие настройки.

### Доступность

- страница «Доступность» (I5, базовый слайс) содержит два переключателя: «Уменьшить движение» и «Высокая контрастность». Значения сохраняются в `settings.json` (`reduceMotion`, `highContrast`);
- **уменьшить движение** отключает анимации оболочки: подъём и масштаб плиток dock применяются мгновенно, без плавного перехода;
- **высокая контрастность** перекрашивает интерфейс в системные цвета темы высокой контрастности Windows: фон, текст, границы и выделение берутся у системы, приглушённые оттенки и стекло (Acrylic в dock и верхней панели) заменяются непрозрачными, а брендовый градиент становится сплошным;
- системные ограничения учитываются всегда и сильнее пользовательских настроек: если в Windows выключены анимации, оболочка их не показывает, а если включена тема высокой контрастности — интерфейс остаётся контрастным, даже если переключатель в Glaze Shell выключен;
- клавиатура: у иконочных кнопок, переключателей, полей и элементов списков заданы озвучиваемые имена (например, «Назад», «Вперёд», «Обновить», «Предпросмотр выбранного элемента», «Поиск Glance», «Центр управления»), а у элементов с фокусом виден акцентный ринг 2 px;
- ограничения базового слайса: полного обхода Narrator (роли и состояния у собственных шаблонов), озвучивания результатов Glance, масштаба текста и альтернативных текстов для иконок нет.

### Восстановление

- страница «Восстановление» (I2, базовый слайс) содержит переключатель «Клавиша восстановления» (вкл./выкл.), поле с сочетанием клавиш и переключатель «Безопасный режим». Значения сохраняются в `settings.json` (`recoveryHotkeyEnabled`, `recoveryHotkeyId`, `safeModeEnabled`);
- сочетание клавиш для восстановления должно быть редким: допускаются только `F1`–`F12` и не менее трёх модификаторов (`Ctrl`, `Alt`, `Shift`, `Win`), по умолчанию `Ctrl+Alt+Shift+F12`. Нераспознанное значение заменяется значением по умолчанию;
- три способа вернуть интерфейс:
  - клавиша восстановления (по умолчанию `Ctrl+Alt+Shift+F12`) — работает всегда, пока она включена в настройках; если комбинацию заняла другая программа, в журнал пишется предупреждение;
  - кнопка «Восстановить UI» в шапке главного окна;
  - ключ командной строки `GlazeShell.exe --restore-ui` — возвращает интерфейс, показывает системное сообщение и завершает работу;
- сторож: при старте оболочка запускает отдельный процесс того же исполняемого файла с ключом `--watchdog <pid>`. Он наблюдает за главным процессом и, если тот был убит, возвращает системную панель задач и значки рабочего стола на место (обычно около секунды, требуется не больше трёх);
- безопасный режим включается ключом `--safe-mode`, переключателем в настройках или автоматически — после трёх падений за пять минут. В нём оболочка ничего не меняет в системе: не запускаются источники системных событий, не создаются dock и верхняя панель, системная панель задач не скрывается. Главное окно при этом открывается;
- ограничения базового слайса: команды восстановления из трея нет (значка трея в проекте нет), восстановление скрытых и cloaked-окон чужих приложений не выполняется (Glaze Shell чужие окна не скрывает), баннера безопасного режима в интерфейсе нет (есть только запись в журнале), ручного сброса счётчика падений нет, а отдельный крошечный исполняемый файл сторожа не собирается — сторож это тот же файл в отдельном процессе без создания окон.

### Верхняя панель

- верхняя панель (A6, базовый слайс): плавающая topmost-панель из трёх pill — значок и имя активного приложения с заголовком окна, строка поиска Glance (подсказка `Ctrl K`) и статус (сеть, громкость, батарея, загрузка ЦП и ГП) с часами и датой. Индикатор ГП показывается только при доступном счётчике производительности, а значок приложения запрашивается в пикселях отображения, поэтому остаётся резким при масштабе 125 % и выше. Окно обрезано по границам плиток, поэтому Acrylic-фон заполняет только сами pill, а промежутки прозрачны; панель не забирает фокус (ввод поиска включается по клику или `Ctrl K`), позиционируется на основном мониторе с учётом DPI и обновляется раз в секунду. Когда активна чужая программа, панель полностью уезжает за верхний край и выезжает только от касания кромки экрана. Включается на странице «Верхняя панель» в настройках, выбор сохраняется в `settings.json` (`topBarEnabled`);
- из возможностей полной панели пока нет: резервирования рабочей области (окна могут перекрывать панель), отдельной панели на каждый монитор и размещения иконок трея.

### Центр управления

- клик по правому pill верхней панели открывает стеклянный popover «Центр управления» (D1, базовый слайс). Он живёт в том же окне, что и Glance, поэтому Acrylic остаётся настоящим; окно на время показа разрешает активацию, и клик мимо (или переход в другое приложение) закрывает popover. Поиск Glance и «Центр управления» взаимно исключены: открытие одного закрывает другое;
- **звук** — реальный уровень устройства вывода по умолчанию (Win32 Core Audio, `IAudioEndpointVolume`): ползунок 0–100 применяется сразу, кнопка «без звука» переключает mute и меняет свой глиф, справа видно текущее значение или «Выключен». Пока popover открыт, уровень перечитывается раз в секунду, поэтому изменения клавишами мультимедиа, системным микшером или другим приложением видны в интерфейсе. Если устройства вывода нет, ползунок и кнопка отключаются с пояснением «Устройство вывода не найдено»;
- **оформление** — тот же выбор режима (Системная/Светлая/Тёмная), что и на странице «Оформление» в настройках: смена сохраняется в `settings.json` (`themeMode`) и сразу применяется и к верхней панели, и к главному окну;
- **система** — быстрые ссылки на страницы настроек Windows: Сеть (`ms-settings:network`), Bluetooth (`ms-settings:bluetooth`) и Звук (`ms-settings:sound`); после открытия настроек popover закрывается сам;
- ограничения базового слайса: переключателей Wi-Fi/Bluetooth/авиарежима нет (WinRT-радио требует упаковки Windows), яркость (WMI/DDC-CI), «Ночной свет» и «Фокус» не реализованы, выбор устройства вывода не добавлен. «Тёмная тема» здесь меняет оформление Glaze Shell, а не системную тему Windows.

### Часы и календарь

- клик по часам в правом pill открывает стеклянный popover календаря (D4, базовый слайс). Он живёт в том же acrylic-окне, что и остальные панели, и использует ту же геометрию, что «Центр управления» (ширина 380, радиус 32). Glance, «Центр управления» и календарь взаимоисключающие: открытие одного закрывает другое, а клик по часам больше не открывает быстрые настройки;
- сетка месяца — всегда шесть недель по семь дней; первый день недели и названия месяцев берутся из текущей культуры (`CultureInfo.CurrentCulture`). Сегодняшний день обведён акцентным кольцом, дни соседних месяцев приглушены, выходные не выделяются;
- навигация: кнопки «‹» и «›» листают месяцы, «Сегодня» возвращает к текущему месяцу (в текущем месяце кнопка неактивна). При каждом открытии календарь показывает текущий месяц;
- закрытие: `Esc`, повторный клик по часам или клик мимо popover;
- ограничения базового слайса: списка событий и задач нет (интеграция с календарём Windows или ICS — позже), недельного и дневного вида, выбора месяца и года из заголовка, номеров недель, нескольких календарей и праздников тоже нет.

### Глобальный поиск Glance

- `Ctrl K` работает в любом приложении: верхняя панель разрешает активацию, ставит фокус в строку поиска и показывает до 6 похожих результатов в стеклянной панели прямо под собой. Если комбинацию заняла другая программа, Glaze Shell продолжит работать без неё (в лог попадёт предупреждение);
- искать можно приложения, открытые окна, страницы системных настроек (`ms-settings:`) и команды Glaze Shell (открыть главное окно, обновить список приложений, открыть «Загрузки» и корзину). Результаты ранжируются по совпадению названия, пояснения и ключевых слов (у приложений добавляется имя exe-файла);
- клавиатура и мышь: `↑`/`↓` двигают выбор, `Enter` открывает, `Esc` очищает, клик по строке результата открывает её, клик мимо панели закрывает поиск;
- ограничения базового слайса: нет поиска по файлам (индекс Windows Search), калькулятора и конвертаций, истории буфера и веб-fallback; результаты выводятся с глифом категории, без иконок приложений.

### Dock

- внизу основного монитора находится dock (A1, базовый слайс): стеклянная Acrylic-капсула с плиткой «Пуск», закреплёнными приложениями и запущенными приложениями с индикатором. Контур у панели не рисуется: форму задаёт региональная маска, а «стеклянность» даёт преломление фона за рамкой и лёгкая тонированная заливка. Панель прижата к нижнему краю экрана и растворяется в нём: нижние углы прямые, скруглены только верхние, поэтому окно обрезано маской со скруглённым верхом. При движении курсора плитки увеличиваются непрерывно: под курсором — до 1.2 и подъём 12 px, соседняя — около 1.06 и 6 px (гауссов спад от расстояния), а у плитки под курсором появляется акцентная рамка; над плиткой появляется компактная pill-подсказка с именем;
- включение и выключение — переключателем «Dock» на странице «Dock» в настройках; выбор сохраняется в `settings.json` (`dockEnabled`);
- клик по незапущенному приложению запускает его, по запущенному — переключает на его окно, а повторный клик по активному приложению сворачивает окно. Правый клик открывает меню «Закрепить в Dock»/«Открепить из Dock», а у запущенного приложения — ещё и «Переключиться на окно». Список закреплённых хранится в `settings.json` (`dockPinnedApps`);
- в конце ленты — системная секция по DESIGN §7.5: папка «Загрузки» (открывает `shell:Downloads`) и корзина (открывает `shell:RecycleBinFolder`), правый клик по ним даёт «Открыть»;
- в dock попадают и запущенные приложения, которых нет в меню «Пуск» (портативные, распакованные): несколько окон одной программы группируются в одну плитку по пути исполняемого файла;
- переключатель «Вместо панели задач» (`dockReplacesTaskbar`, по умолчанию включён) скрывает системную панель задач, пока работает dock. Панель задач не удаляется и настройки Windows не меняются: её окно сдвигается за нижний край монитора и возвращается при закрытии приложения, выключении dock или этого переключателя. После перезапуска Explorer скрытие повторяется, а если приложение завершилось аварийно — панель вернётся при следующем запуске (или перезапуске Explorer);
- ограничения базового слайса: одна панель на основном мониторе, нет перетаскивания плиток, импорта закреплений панели задач, бейджей, стопок папок, popover-карточки папки, «Empty» у корзины и анимации сворачивания окон; рабочая область не резервируется, поэтому развёрнутые окна могут перекрывать dock.

### Проводник

- кнопка «Проводник» в шапке главного окна и команда `open-explorer` в Glance открывают окно проводника (E1/E2, базовый слайс). Окно одно и переиспользуется: повторное открытие показывает уже существующее окно и, если передана папка, переходит в неё;
- слева — сайдбар по DESIGN §7.2: системные папки (Пользователь, Рабочий стол, Загрузки, Документы, Изображения, Музыка, Видео), пользовательское избранное и диски (буква, тип, общая ёмкость и доля заполнения). Кнопка «В избранное» добавляет текущую папку, правый клик по записи избранного удаляет её; список хранится в `settings.json` (`explorerFavorites`, до 32 путей) и переживает перезапуск;
- два вида из четырёх: **иконки** (сетка карточек) и **список** (колонки Имя/Изменён/Размер); вид переключается в тулбаре и запоминается в `settings.json` (`explorerViewMode`);
- сортировка — по имени, дате, размеру или типу, направление переключается повторным кликом по колонке; папки всегда идут первыми, порядок стабильный;
- навигация: кнопки «Назад»/«Вперёд»/«Выше», `Enter` открывает выбранную папку, стрелки двигают выбор; чтение каталога идёт в фоне, а недоступные папки не роняют окно. Скрытые и системные элементы в списках не показываются;
- ограничения базового слайса: нет колонок Миллера и галереи, миниатюр с дисковым кэшем и виртуализации огромных каталогов, вкладок и строки пути (E3), тегов (E4), панели Get Info (E5), перетаскивания папок в сайдбар и извлечения съёмных дисков.

### Quick Preview

- клавиша `Пробел` на выбранном элементе проводника (или кнопка «Предпросмотр» в тулбаре) открывает карточку предпросмотра (B2, базовый слайс): имя файла, вид/размер/дата, содержимое и нижняя строка с полным путём;
- **картинки** (png, jpg, gif, bmp, webp, svg и др.) декодируются WinUI и показываются целиком в границах карточки; файл крупнее 512 МБ не рисуется, а повреждённый снимок заменяется глифом;
- **текст и код** (txt, log, md, json, xml, csv, cs, py, js, html и др.) читаются в фоне: кодировка определяется по BOM (UTF-8, UTF-16), текст выделяется мышью, показывается первые 256 КБ или 120 000 символов — остаток отсекается с пометкой внизу;
- **папка** показывает сводку по числу элементов (счёт ограничен 10 000), **аудио, видео, архивы и прочее** — метаданные, глиф и кнопку «Открыть» в приложении по умолчанию;
- файл открывается на чтение с общим доступом, поэтому предпросмотр не мешает другим приложениям и не выполняет содержимое. Закрыть карточку — `Esc`, `Пробел` или кнопка; «Копировать путь» кладёт полный путь в буфер обмена;
- ограничения базового слайса: нет предпросмотра PDF/Office (`IPreviewHandler`), проигрывания аудио/видео, зума, «Открыть с помощью», навигации по выборке стрелками, предпросмотра в стандартном проводнике Windows и `Tab`-предпросмотра из Glance.

### Persistence

- persistence: JSON-документы пользовательских данных (`config.json`, `settings.json`, `layout.json`) с версией схемы, цепочкой миграций, атомарной записью, резервными копиями и изоляцией повреждённых документов; лимиты размера и глубины разбора; пути берутся только из кода.

### Application lifecycle

- application lifecycle: одиночный экземпляр через именованный mutex (`SingleInstanceHelper`/`SingleInstanceLease`), который удерживается весь срок работы; повторный запуск находит окно уже работающего экземпляра, восстанавливает его из свёрнутого состояния и завершает новый процесс. Окно сопоставляется по владеющему процессу (сравнение пути исполняемого файла), а при закрытии окна освобождаются подписки событий, layout-writer, настройки и mutex;
- состояние сессии и страховка от падений: `recovery.json` в корне пользовательских данных помечает сессию незавершённой при запуске и завершённой при штатном выходе, поэтому незавершённая прошлая сессия читается как падение. Счётчик падений (три за пять минут) включает безопасный режим, а отдельный процесс-сторож (`--watchdog <pid>`) возвращает интерфейс, если главный процесс был убит.

### Прочее

- файловое логирование в `%LOCALAPPDATA%\GlazeShell\logs`.

### Планируемые возможности

- кастомизация рабочего стола и настройка визуальной стороны (темы, оформление) — дизайн-система и план функций в стиле macOS описаны в [DESIGN.md](DESIGN.md) и [FEATURES.md](FEATURES.md);
- автозапуск приложения при входе в систему;
- будущая система виджетов и расширений; см. подробный перечень в [FEATURES.md](FEATURES.md).

## Как пользоваться приложением

После запуска открывается главное окно из двух колонок: слева — список установленных приложений с поиском и действиями, справа — панель «Мониторы». В шапке справа — кнопки «Восстановить UI», «Проводник» и «Настройки»; тема, акцент, верхняя панель, dock и замена системной панели задач настраиваются в окне настроек. Строка состояния внизу показывает время последнего обновления и путь к данным.

### Поиск и обновление

- Поле поиска фильтрует приложения по названию, пути или AUMID по мере ввода.
- Кнопка «Обновить» или клавиша `F5` запускают повторное сканирование; пока идёт сканирование, кнопка блокируется, а по завершении в статусе появляется отметка времени.
- Если совпадений нет, выводится «Приложения не найдены».

### Список приложений

- Карточка показывает название, описание, тип (Win32 или MSIX) и состояние: приложение не запущено / запускается (круговой индикатор) / запущено (акцентная точка).
- Кнопка «Копировать» рядом с путём кладёт в буфер обмена полный путь к исполняемому файлу (для MSIX — AUMID или имя семейства пакета).
- У запущенного приложения под карточкой раскрывается панель его окон.

### Действия с приложением

Кнопки под списком применяются к выбранной карточке:

- **Запустить** — запуск приложения (Win32 через `ProcessStartInfo`, MSIX через `IApplicationActivationManager`).
- **Закрыть** — вежливое закрытие (`CloseMainWindow`, а при отсутствии главного окна — `WM_CLOSE` по окнам процесса).
- **Перезапустить** — закрытие с ожиданием и последующий запуск; если вежливо закрыть не удалось, выполняется принудительное завершение, чтобы рядом не поднялся второй экземпляр.
- **Завершить принудительно** — снятие дерева процессов зависшего приложения; действие требует подтверждения в диалоге.

### Клавиатурная навигация

| Клавиша | Действие |
| --- | --- |
| `↑` / `↓` | перемещение по списку (выбранный элемент подносится к видимой области) |
| `Enter` | запуск выбранного приложения |
| `Space` | запуск выбранного приложения, когда фокус не в поле поиска |
| `F5` | обновить список |
| `Esc` | очистить поле поиска |

### Окна приложения

В панели окон под карточкой и в панели «Мониторы» для каждого окна доступны:

- **Фокус** — поднять окно; фокусировка best-effort и при отказе `SetForegroundWindow` использует fallback через `AttachThreadInput`;
- **Свернуть** / **Развернуть** — свернуть, развернуть и восстановить окно;
- **Закрыть** — вежливое закрытие окна через `WM_CLOSE`.

### Панель «Мониторы»

- Сводка по мониторам и карточка на каждый: разрешение, DPI/scale factor, refresh rate, ориентация и признак основного дисплея.
- Схематичная карта раскладки мониторов и список окон, открытых на каждом из них; обновление происходит по событиям дисплеев.
- Кнопка **Имя** открывает диалог переименования дисплея: «Сохранить» задаёт пользовательское имя, «Сбросить» возвращает имя по умолчанию, «Отмена» ничего не меняет. Имя сохраняется в `settings.json` и переживает перезапуск.

### Проводник

- Открыть проводник можно кнопкой «Проводник» в шапке главного окна или командой `open-explorer` через `Ctrl K`;
- слева выбираются системная папка, запись избранного или диск; справа — содержимое папки в виде сетки карточек или списка с колонками;
- клик по колонке (или по кнопке направления в тулбаре) меняет сортировку; двойной клик по папке или `Enter` входит в неё, кнопки «Назад»/«Вперёд»/«Выше» возвращают назад по истории;
- кнопка «В избранное» запоминает текущую папку, правый клик по записи избранного в сайдбаре удаляет её;
- внизу окна — путь текущей папки и число элементов, кнопка «Обновить» перечитывает содержимое.

### Quick Preview

- Выберите элемент стрелками или мышью и нажмите `Пробел` (или кнопку «Предпросмотр» в тулбаре) — откроется карточка предпросмотра.
- Картинка показывается целиком; текст открывается моноширинным шрифтом и выделяется мышью; для папки выводится число элементов; для аудио, видео и архива — метаданные и кнопка «Открыть».
- «Открыть» запускает файл в приложении по умолчанию, «Копировать путь» кладёт полный путь в буфер обмена.
- Закрыть карточку — `Esc`, `Пробел` или кнопка с крестом; открывается только одна карточка одновременно.

### Один экземпляр и завершение

Приложение работает в одном экземпляре: повторный запуск не открывает второе окно, а поднимает уже работающее. Закрытие окна корректно освобождает ресурсы (подписки событий, layout-writer, single-instance mutex), поэтому приложение можно запустить снова.

## Данные и логи

При первом запуске создаётся каталог пользовательских данных `%LOCALAPPDATA%\GlazeShell`:

```text
%LOCALAPPDATA%\GlazeShell\
├── config.json     # имя приложения и каталог данных
├── settings.json   # пользовательские настройки
├── layout.json     # вкладки, категории и раскладка
├── recovery.json   # состояние сессии и история падений (сторож и безопасный режим)
├── themes/         # пользовательские темы (*.json)
├── backups/        # резервные копии перед миграциями
├── recovery/       # изолированные повреждённые документы
└── logs/
    └── glaze-shell.log   # startup-лог и диагностика
```

Имя каталога данных задаётся полем `dataDirectoryName` в `config.json`, поэтому путь к данным задаётся пользователем без правки кода. При смене каталога лог текущей сессии остаётся в исходном каталоге.

## Ограничения текущего MVP

- Выбор оформления (тема и акцент) применяется к интерфейсу Glaze Shell; пользовательские темы из `themes/*.json`, панель вкладок и категорий пока не подключены к UI: backend тем, вкладок/категорий и layout готов и покрыт тестами, визуальная часть — следующий этап.
- Dock — базовый слайс: одна панель на основном мониторе, без перетаскивания плиток, бейджей, стопок папок, popover-карточки папки и анимации сворачивания окон; рабочая область не резервируется.
- «Центр управления» (D1) — базовый слайс: реальная громкость, режим оформления и ссылки на системные настройки; переключателей Wi-Fi/Bluetooth/авиарежима, яркости, «Ночного света» и «Фокуса» нет.
- «Часы и календарь» (D4) — базовый слайс: сетка месяца с навигацией, сегодняшним днём и локалью; списка событий и задач, недельного/дневного вида, выбора месяца и года, номеров недель, нескольких календарей и праздников нет.
- «Проводник» (E1/E2) — базовый слайс: два вида (иконки и список), сортировка, навигация, системные папки, избранное и диски; колонок Миллера, галереи, вкладок и строки пути, тегов, Get Info, перетаскивания папок в сайдбар и извлечения съёмных дисков нет.
- Quick Preview (B2) — базовый слайс: картинки, текст/код, сводка папки и метаданные; PDF/Office, проигрывание аудио/видео, зум, «Открыть с помощью» и предпросмотр в стандартном проводнике Windows нет.
- Приложение поставляется как unpackaged (без MSIX): Installer и подпись появятся позже.
- Доступность (I5) — базовый слайс: работают «Уменьшить движение» и «Высокая контрастность», учитываются системные ограничения Windows, у собственных контролов есть озвучиваемые имена и видимый фокус-ринг; полного обхода Narrator, озвучивания результатов Glance, `AutomationPeer` для плиток dock, масштаба текста и альтернативных текстов для иконок нет.
- Восстановление и сторож (I2) — базовый слайс: работают клавиша восстановления, кнопка «Восстановить UI», ключ `--restore-ui`, сторож отдельным процессом и безопасный режим по счётчику падений; команды восстановления из трея нет, восстановление скрытых и cloaked-окон чужих приложений не выполняется, баннера безопасного режима в интерфейсе нет.
