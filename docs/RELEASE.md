# Release

Документ описывает процесс подготовки и публикации релиза Glaze Shell. Release workflow введён на Stage 13: он документирован и содержит проверяемый чеклист, но не выполняет автоматическую сборку и не публикует бинарники без отдельного решения.

## Принципы

- **Единый источник версии.** Версия задаётся один раз в `Directory.Build.props` (`Version`, `AssemblyVersion`, `FileVersion`) и применяется ко всем проектам решения. Менять версию нужно только там.
- **SemVer.** Схема — `MAJOR.MINOR.PATCH`. Пока у приложения нет стабильного публичного API, версия остаётся в диапазоне `0.x`; первый релиз — `0.1.0`.
- **Детерминированная сборка.** `Deterministic=true` и `ContinuousIntegrationBuild=true` включены в `Directory.Build.props`, поэтому один и тот же исходник даёт одинаковый бинарник независимо от машины. `AssemblyVersion` и `FileVersion` — четырёхкомпонентные (`0.1.0.0`) и синхронизированы с `Version`, а `InformationalVersion` SDK формирует из `Version`.
- **Без CI.** Автоматический пайплайн (GitHub Actions и аналогичный) намеренно не вводится: сборка и публикация выполняются локально по чеклисту, чтобы требования (Windows, Windows App SDK, x64) не дублировались в конфигурации, которую никто не поддерживает. Если появится потребность, пайплайн добавляется вместе с Installer, а не раньше.
- **Unpackaged-поставка.** Приложение собирается как unpackaged (без package identity) с self-contained Windows App SDK. Installer и MSIX-пакет отсутствуют; пока их нет, собранный `GlazeShell.exe` нельзя публиковать как готовый релиз для конечных пользователей.

## Предварительные условия

- Windows 10 1809 (`10.0.17763.0`) или новее, `x64`.
- .NET SDK, разрешённый `global.json` (`10.0.401`, `rollForward: latestPatch`).
- Чистое рабочее дерево Git (`git status` без незакоммиченных изменений) и актуальная ветка.

## Чеклист релиза

1. **Версия.** Обновить `<Version>`, `<AssemblyVersion>` и `<FileVersion>` в `Directory.Build.props` (суффикс `0` у двух последних сохраняется).
2. **Документация.** Убедиться, что `CHANGELOG.md` содержит раздел с итогом релиза, а `README.md` и `docs/` согласованы с реализацией (включая бейдж и таблицу Roadmap).
3. **Сборка Debug.** `dotnet build GlazeShell.slnx -c Debug --nologo` — ожидается `0 warnings / 0 errors`.
4. **Сборка Release.** `dotnet build GlazeShell.slnx -c Release --nologo` — ожидается `0 warnings / 0 errors`.
5. **Тесты.** `dotnet test GlazeShell.slnx -c Release --nologo` — все тесты должны пройти. Environment-tolerant тесты, недоступные в среде, завершаются `Inconclusive` с объясняющим warning и не считаются провалом.
6. **Ручная проверка.** Запустить `glaze.cmd Release` и проверить startup: окно появляется, лог создаётся, повторный запуск поднимает существующий экземпляр и завершает новый процесс.
7. **Diff.** Просмотреть `git diff` и убедиться, что в релиз не попали временные файлы и секреты (см. `.gitignore` и [docs/SECURITY.md](SECURITY.md)).
8. **Коммит.** Один логически завершённый коммит с версией и итогом релиза; сообщение — на русском языке в стиле истории проекта.
9. **Тег.** Пометить коммит тегом версии (`git tag v0.1.0`) и запушить (коммит и тег отдельными командами).

## Команды

```powershell
# Проверка сборки
dotnet build GlazeShell.slnx -c Debug --nologo
dotnet build GlazeShell.slnx -c Release --nologo

# Тесты
dotnet test GlazeShell.slnx -c Release --nologo
dotnet test .\tests\GlazeShell.Windows.Tests\GlazeShell.Windows.Tests.csproj -c Release

# Ручной запуск собранного приложения
glaze.cmd Release
```

## Артефакты

Релизный артефакт — собранный `GlazeShell.exe` и его зависимости:

```text
src\GlazeShell.App\bin\x64\Release\net10.0-windows10.0.19041.0\win-x64\
```

Каталог содержит приложение и self-contained Windows App SDK, поэтому рантайм Windows App SDK отдельно не требуется. Архитектура — только `x64`.

## Что не входит в релиз

- **Installer и MSIX.** Упаковка остаётся отдельной задачей вместе с Installer: до её появления приложение запускается как unpackaged и не имеет package identity.
- **Автопубликация.** Бинарники не загружаются на внешние площадки и не прикладываются к GitHub Releases автоматически.
- **Автозапуск при входе в систему.** Остаётся отдельной задачей (см. [docs/ARCHITECTURE.md](ARCHITECTURE.md)).

## Откат

Перед публикацией тега можно безопасно откатить изменения: версия меняется в одном файле, а коммит и тег создаются последними. Если после тега обнаружена регрессия, версия поднимается следующим `PATCH`, а исправление оформляется новым коммитом — тег существующего релиза не перезаписывается.
