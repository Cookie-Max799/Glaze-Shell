# Roadmap Glaze Shell

Статусы: ✅ — завершено, ⏳ — планируется, ⚪ — не планируется.

> **Термин «MVP».** В проекте под MVP понимается инженерный фундамент оболочки — технические стадии 0–13, все завершены. В продуктовом плане [FEATURES.md](FEATURES.md) под MVP также обозначается полноценная оболочка (dock, top bar, Glance и др.); она ещё не начата, поэтому Phase 1 остаётся ⏳. Продуктовый UI начат с функции H1 «движок тем», затем A6 «Top bar», A1 «Dock» и B1 «Glance» (базовые слайсы).

## Текущий статус по стадиям

- **Stage 13 — Testing и Release завершён.** Расширено покрытие: добавлены тесты для доменной логики, которая раньше проверялась только косвенно — идентификаторы приложений и ключи запуска (`ApplicationIdentity`), discovery-сервис на фейковых источниках (`ApplicationDiscoveryService` с кэшем, слиянием кандидатов, изоляцией отказа источника и лимитом предупреждений), валидация опций discovery и наблюдения за процессами, мапперы документов (`LayoutDocumentMapper`, `SettingsDocumentMapper`, `ConfigurationDocumentMapper`), лимиты `PersistenceLimits`, результат миграции, события оболочки (`GlazeEvents`), а также `ProcessInspector` по каталогу и по имени образа. Общее число тестов выросло с 357 до 475. Введён процесс релиза: версия задаётся один раз в `Directory.Build.props` (SemVer, `0.1.0`) и применяется ко всем проектам, а шаги и чеклист выпуска описаны в [RELEASE.md](RELEASE.md). Автоматический CI не вводится — сборка и публикация выполняются локально.
- **Stage 12 — Security завершён.** Проведён обзор поверхности безопасности и закрыты найденные границы: чтение документов и тем идёт через один открытый дескриптор с ограничением по байтам (подмена файла между проверкой размера и чтением больше не обходит лимит), имена документов дополнительно отклоняют зарезервированные имена устройств (`CON`, `NUL`, `COM1`…) и завершающие точку/пробел, которые Win32 отбрасывает, `LogRedactor` маскирует пути профиля в обоих разделителях и JSON-экране, многословные секреты, расширенный набор ключей и токены `Bearer` с нестандартными символами, а также не рвёт суррогатную пару при обрезке; список запрещённых расширений тем дополнен ярлыками и установщиками. Расширение принудительного завершения по каталогу больше не распространяется на `C:\Windows` и его подкаталоги и на общие корни установки (`C:\Program Files`, `C:\Program Files (x86)`, `C:\ProgramData`), при этом подкаталог конкретной программы остаётся безопасным. Снятие WinEvent-хуков выполняется потоком-владельцем, а не потоком остановки.
- **Stage 11 — Performance завершён.** Добавлена измерительная инфраструктура для профилирования фоновых ресурсов без слепых оптимизаций: при запуске снимается baseline (working set, managed heap, потоки, handles, CPU, uptime) и по закрытию окна пишется итог сессии с приращениями и средней загрузкой CPU. Задержка синхронной доставки событий измеряется в `EventManager` через `EventLatencyRecorder` (count/avg/min/max). Постоянный таймер idle-профилирования выключен по умолчанию и включается переменной окружения `GLAZESHELL_PERF_INTERVAL_MS`.
- **Stage 10 — Application Lifecycle завершён.** Реализован единый жизненный цикл экземпляра приложения: одиночность запуска через именованный mutex, который удерживается весь срок работы (`SingleInstanceLease`), а повторный запуск находит окно уже работающего экземпляра, поднимает его и завершает новый процесс. При закрытии окна освобождаются layout-writer, источники событий и сам mutex (последним), поэтому экземпляр можно запустить заново; окно, созданное другим процессом, сопоставляется по владеющему процессу, а не по пути модуля.
- **Stage 9 — Windows Events завершён.** Источники системных событий запускаются из одной точки (`ShellEventCoordinator`): оконные события (`SetWinEventHook`), события дисплеев (hidden message window) и события процессов (`ProcessEventMonitor`). Отказ отдельного источника не прерывает запуск остальных — диагностика попадает в `ShellEventStatus.Diagnostics` и лог, а `Start()` возвращает флаг по каждому источнику. Состояние запущенных приложений обновляется по событиям `ProcessStarted`/`ProcessExited` вместо опроса каждые 3 секунды, а пачка событий одного запуска объединяется вместо пересчёта на каждое событие.
- **Stage 8 — Theme System завершён.** Реализован backend тем: `ThemeManager` хранит набор тем, выбирает действующую тему (по `UserSettings.ActiveThemeId`) и публикует `ThemeChanged`; `ThemeStore` читает пользовательские темы из каталога `themes` в каталоге данных приложения. Тема содержит только данные оформления (`metadata`, `colors`, `fonts`, `dimensions`, `icons`, `wallpaper`, `effects`): исполняемые ассеты, пути вне каталога темы и нечисловые выражения цвета отклоняются, непригодная тема отбрасывается по отдельности и не портит остальные, а при отсутствии тем применяется встроенная тема `glaze-default`. Решение о том, как отображать значения темы, остаётся за UI.
- **Stage 7 — Persistence завершён.** Реализовано сохранение пользовательских данных в JSON (`config.json`, `settings.json`, `layout.json`): версия схемы в каждом документе, цепочка миграций с резервной копией перед перезаписью, атомарная запись, изоляция повреждённых документов в `recovery` и неприкосновенность документов из будущих версий приложения. Layout восстанавливается между запусками вместе с привязкой вкладок к мониторам: привязки к недоступным мониторам снимаются, а результат сверки сразу сохраняется. Автосохранение layout выполняет `DesktopLayoutPersistenceWriter`, объединяя частые изменения в одну запись.
- **Stage 6 — Tabs and Categories завершён.** Реализован полный backend рабочего пространства: вкладки (создание, удаление, переименование, перемещение, активация), категории (создание, удаление, переименование, перемещение) и размещение приложений (добавление, удаление, перенос между категориями) с единым каноническим порядком `Order` на трёх уровнях layout. `DesktopTab.IsActive` удалён как дублирующее поле — единственный источник активной вкладки `DesktopLayout.ActiveTabId`.
- **Stage 5 — Desktop Integration завершён.** Реализованы мониторы и DPI (перечисление, resolution, refresh rate, ориентация, scale factor, primary), display events через `WM_DISPLAYCHANGE`, desktop layout (вкладки и элементы) через `DesktopManager`; в футере отображается панель «Мониторы» с обновлением по событиям.
- **Stage 4 — Window Manager завершён.** Реализовано перечисление видимых top-level окон, события окон (открытие, закрытие, foreground, изменение состояния), фокус, свернуть/развернуть/восстановить через `ShowWindowAsync` и закрытие через `WM_CLOSE`; в карточках запущенных приложений отображается инлайн-панель их окон.
- **Stage 3 — Application Launcher завершён.** Реализованы запуск, проверка состояния и закрытие приложений (Win32 + MSIX), а также простой UI лаунчера с поиском и горячими клавишами.
- **Stage 2 — Application Discovery завершён.** Реализовано обнаружение приложений из меню «Пуск» (`.lnk`) и пакетов MSIX/AppsFolder через официальные Windows API.
- **Stage 1 — Core завершён.** Реализованы доменные модели, контракты интерфейсов, события и базовые framework-free сервисы `GlazeShell.Core`.
- **Stage 0 — Foundation завершён.** Создана минимальная запускаемая WinUI 3 оболочка, слоистая структура .NET-решения, базовая конфигурация, централизованное файловое логирование и тестовый проект.

## Продуктовый прогресс

- **Phase 1 — H1 «Движок тем» завершён.** В интерфейсе появился переключатель оформления: режим (Системная/Светлая/Тёмная) и акцентный цвет (6 вариантов плюс «по умолчанию»). В Core добавлены `ThemeMode`, `AccentPalette` и `ThemeModeResolver`, `UserSettings` получил `ThemeMode`/`AccentId`; в `settings.json` добавлены `themeMode`/`accentId` без смены `schemaVersion`. В App введены токены-кисти в `App.xaml` и `ThemeApplicator`, который переключает `RequestedTheme` и перекрашивает кисти на месте; `MainWindow.xaml` переведён с hex-цветов на токены. Режим «Системная» читает системную настройку `AppsUseLightTheme`. Движок меняет только интерфейс Glaze Shell. Общее число тестов — 489 (Core 260, Data 133, Windows 96). Следующие функции Phase 1: Quick Settings, Glance и др.
- **Phase 1 — A6 «Top bar» (базовый слайс) реализован.** Над рабочим столом появилась плавающая верхняя панель из трёх pill (имя активного приложения с шевроном и расположением, строка поиска с подсказкой `Ctrl K`, статус — сеть, громкость, батарея — и часы с датой); системный Acrylic-фон заполняет только сами pill, потому что окно обрезано региональной маской по их границам (`SetWindowRgn`, `OverlayWindow.ApplyRoundedRegions`). Окно — topmost инструментальное и non-activating, не крадёт фокус (ввод поиска включается по клику), позиционируется на основном мониторе с учётом DPI и обновляется раз в секунду; включается переключателем «Верхняя панель» в шапке (`settings.json`, `topBarEnabled`). В `GlazeShell.Windows` добавлены `WindowManagement/OverlayWindow`, `SystemStatus/SystemStatusProvider` (батарея и сеть) и `Applications/ApplicationNameResolver`; в интероп — `SetWindowLongPtr`, `ShowWindow`, `SetWindowRgn`, `CreateRoundRectRgn`/`CombineRgn`, `DwmSetWindowAttribute` (corner preference) и `GetSystemPowerStatus`. Не реализованы (следующие шаги): резервирование рабочей области (AppBar `SHAppBarMessage`), отдельная панель на каждый монитор, размещение иконок трея, popover часов и календаря (D4) и чтение громкости. Общее число тестов — 492 (Core 262, Data 134, Windows 96).
- **Phase 1 — A1 «Dock» (базовый слайс) реализован.** Внизу появилась капсула dock «жидкого стекла», прижатая к нижнему краю экрана и растворяющаяся в нём: плитка «Пуск», закреплённые и запущенные приложения с индикатором, разделители секций, папка «Загрузки» и корзина (открывают `shell:Downloads`/`shell:RecycleBinFolder`). Окно обрезано маской с прямым нижним краем, поэтому Acrylic-стекло рисуется только внутри панели; наведение даёт непрерывную магнификацию вокруг курсора (до 16 px/1.2, сосед ≈ 6 px/1.06) и pill-подсказку (DESIGN §7.5). Закрепление — через контекстное меню, список сохраняется в `settings.json` (`dockPinnedApps`); запущенные приложения обновляются по событиям окон, а приложения вне discovery (портативные) группируются по пути исполняемого файла. Повторный клик по активному приложению сворачивает его окно. Dock включается переключателем «Dock» (`dockEnabled`). Настройка `dockReplacesTaskbar` (по умолчанию включена) скрывает системную панель задач, пока работает dock: `TaskbarHider` сдвигает `Shell_TrayWnd` за край монитора, возвращает его при выходе/выключении и восстанавливается после аварийного завершения. Не реализованы (следующие шаги): перетаскивание плиток, бейджи, стопки папок, popover-карточка папки, анимация сворачивания окон, dock на каждый монитор и резервирование рабочей области. Общее число тестов — 510 (Core 269, Data 140, Windows 101).
- **Phase 1 — B1 «Glance» (базовый слайс) реализован.** Глобальная клавиша `Ctrl K` (`GlazeShell.Windows/Shell/GlobalHotkey`: выделенный поток, невидимое окно, `RegisterHotKey`) открывает поиск в верхней панели, даже когда приложение не в фокусе; если комбинация занята, приложение работает без неё и пишет предупреждение в лог. Ранжирование вынесено в framework-free ядро `GlazeShell.Core/Glance` (`GlanceResult`, `GlanceResultKind`, `GlanceRanker`: точное > префикс > начало слова > вхождение > пояснение > ключевые слова) и покрыто тестами. Кандидаты собирает `Presentation/GlanceSearchCatalog`: приложения (ленивое сканирование с кэшем), открытые окна, страницы `ms-settings:` и команды Glaze Shell. `TopBarViewModel` ранжирует их при вводе и открывает выбранное (запуск приложения, фокус окна, URI настроек, команда), а результаты показываются в стеклянной панели под строкой поиска в том же acrylic-окне (окно растёт по высоте, регион расширяется на панель результатов). Клавиши: стрелки, `Enter`, `Esc`; клик мимо панели закрывает поиск. Не реализованы (следующие шаги): поиск по файлам (индекс Windows Search), калькулятор и конвертации, история буфера, веб-fallback, обучение на выборах, `Ctrl+Enter`/`Tab`/`Alt+1…9` и префикс `>`. Общее число тестов — 525 (Core 284, Data 140, Windows 101).
- **Phase 1 — D1 «Центр управления» (базовый слайс) реализован.** Клик по правому pill верхней панели открывает стеклянный popover в том же acrylic-окне (отдельный слой под pill, ширина 380, радиус 32): **реальная громкость устройства вывода по умолчанию** через Core Audio (`GlazeShell.Windows/Audio/SystemVolumeProvider`: `MMDeviceEnumerator` → `IMMDeviceEnumerator::GetDefaultAudioEndpoint` → `IMMDevice::Activate` → `IAudioEndpointVolume`; ползунок 0–100, кнопка «без звука»), выбор режима оформления (тот же `themeMode`, что и в шапке, поэтому смена сразу применяется к обоим окнам — `MainViewModel` подписан на `SettingsChanged`) и ссылки на системные настройки (`ms-settings:network`, `ms-settings:bluetooth`, `ms-settings:sound`). Громкость обновляется раз в секунду, пока popover открыт, и не зацикливается с применением (значение пишется в поле напрямую); при отсутствии устройства ползунок отключается с пояснением. Региональная маска считает радиус по каждой области (капсула 24 у pill, 32 у панелей — `OverlayWindow.PixelRegion`). Не реализованы (следующие шаги): переключатели Wi-Fi/Bluetooth/авиарежима (`Windows.Devices.Radios` требует упаковки Windows), яркость (WMI/DDC-CI), «Ночной свет» (публичного API нет), «Фокус» (D3) и выбор устройства вывода. Общее число тестов — 526 (Core 284, Data 140, Windows 102).
- **Phase 1 — E1 «Виды» и E2 «Сайдбар: избранное и диски» (базовые слайсы) реализованы.** Появилось окно «Проводник» (кнопка в шапке главного окна и команда Glance `open-explorer`; окно одно и переиспользуется). Два вида из четырёх — **иконки** (сетка карточек с шелл-иконками) и **список** (колонки Имя/Изменён/Размер); вид и избранное хранятся в `UserSettings` (`explorerViewMode`, `explorerFavorites` до 32 путей) и переживают перезапуск. Сортировка по имени/дате/размеру/типу в обе стороны, папки всегда первые, порядок стабильный (`FileSystemSorter`, Core). Навигация назад/вперёд/выше по иерархии, Enter открывает папку; чтение каталога идёт в фоне через `IFileSystemBrowser` (`NativeFileSystemBrowser` в Windows-слое: перечисление с пропуском скрытых/системных и недоступных, диски с ёмкостью и долей заполнения, системные папки). Сайдбар по DESIGN §7.2: системные папки, пользовательское избранное (кнопка «В избранное», контекстное меню) и диски. Не реализованы (следующие шаги): колонки Миллера и галерея, миниатюры с дисковым кэшем и виртуализация больших каталогов, вкладки/строка пути (E3), теги (E4), Get Info (E5), перетаскивание папок в сайдбар и извлечение съёмных дисков. Общее число тестов — 555 (Core 301, Data 146, Windows 108 + 1 пропуск).
- **Phase 1 — B2 «Quick Preview» (базовый слайс) реализован.** Пробел на выбранном элементе проводника (или кнопка «Предпросмотр» в тулбаре) открывает карточку предпросмотра: картинки декодирует WinUI (файл крупнее 512 МБ не рисуется, битый — деградирует до глифа), текст и код читаются в фоне с распознаванием кодировки по BOM и ограничением 256 КБ/120 000 символов (с пометкой об обрезке), папка — со сводкой по числу элементов, остальное — глифом с метаданными и кнопкой «Открыть». Чтение — `IFilePreviewReader` (`Core/Interfaces`) и `NativeFilePreviewReader` (`Windows/FileSystem`), файл открывается с `FileShare.ReadWrite|Delete` и никогда не блокируется; содержимое не выполняется. Карточка закрывается по `Esc`/пробелу и живёт одна на проводник. Не реализованы (следующие шаги): PDF/Office через `IPreviewHandler`, проигрывание аудио/видео, зум, «Открыть с помощью», навигация по выборке стрелками, предпросмотр в стандартном File Explorer и `Tab`-предпросмотр из Glance. Общее число тестов — 568 (Core 306, Data 146, Windows 116).
