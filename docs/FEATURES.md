# Glaze Shell — спецификация возможностей: удобства повседневного использования, в стиле Glaze

Этот документ перечисляет удобства, которые ценят в macOS, и описывает, как Glaze Shell может дать **эквивалентный опыт на Windows** — с нашими именами, нашим дизайном (см. [DESIGN.md](DESIGN.md)) и реалистичными заметками о реализации. Он написан для ИИ-агента-разработчика и для людей, работающих вместе с ним.

## 1. Как пользоваться этим документом

- У каждой функции есть **ID** (A1, B2…), **приоритет** (P0–P3), грубая **сложность** (S/M/L), класс **осуществимости** и **критерии готовности**, которые можно превратить в тесты.
- Реализуйте в порядке приоритетов (раздел 4). Не начинайте пункты P2/P3, пока P0/P1 не стабильны.
- Детали UI (размеры, цвета, радиусы, движение) здесь не повторяются — берите их из [DESIGN.md](DESIGN.md) и `design/tokens/`.
- «Подход на Windows» перечисляет предлагаемые API и техники. Это отправные точки: **проверяйте каждую по актуальной документации Microsoft и целевой сборке Windows перед реализацией**, потому что поведение меняется между релизами.
- Если функция требует продуктового решения, остановитесь и спросите, а не угадывайте.
- Машинный индекс: `features.json` (id, группа, имя, приоритет, сложность, осуществимость, фаза).

Классы осуществимости: **документированный** = публичные поддерживаемые API; **частичный** = работает с ограничениями/условиями; **хрупкий** = опирается на недокументированное поведение, которое может сломаться между сборками Windows; **собственный UI** = полностью наш UI/логика.

## 2. Именование и гигиена ИС

Мы заимствуем *идеи*, а не бренды. Используйте собственные имена в продукте, UI, документации и маркетинге; имена Apple оставляйте только во внутренних заметках «аналог в macOS».

| Наше имя | Какую идею покрывает |
|---|---|
| Dock | Панель запуска/переключения приложений |
| Top bar | Зона статуса + часы (без глобального меню приложений) |
| Glance | Глобальный поиск и лаунчер |
| Quick Preview | Предпросмотр файла по пробелу |
| Overview | Все окна разом |
| Workspaces | Несколько наборов окон с переключением между ними |
| Apps | Полноэкранная сетка приложений |
| Quick Settings | Панель переключателей и слайдеров |
| Explorer | Наш файловый менеджер |
| Capture | Скриншоты и запись экрана |

Не используйте в поставляемом продукте логотипы, иконки, звуки, обои, шрифты или торговые имена Apple. Идеи сочетаний клавиш, поведение и общие концепции переиспользовать можно.

## 3. Проверка реальности Windows

**Мы можем:** полностью оформлять собственные окна; создавать оверлеи, плавающие панели и popover; регистрировать глобальные горячие клавиши; наблюдать и перемещать окна верхнего уровня; показывать живые миниатюры окон; читать список установленных приложений и поисковый индекс; управлять громкостью, яркостью (если позволяет железо), радиомодулями (с разрешением), тёмной темой, обоями; захватывать экран; задавать DWM-атрибуты на поддерживаемых сборках Windows 11.

**Мы не можем (надёжно):**
- Переоформлять чужие заголовки/хром за пределами, разрешёнными DWM-атрибутами (нет пользовательских радиусов у чужих окон).
- Дать настоящее глобальное меню приложений для всех программ.
- Создавать/переключать нативные виртуальные рабочие столы документированными API (документированы лишь ограниченные).
- Читать бейджи/прогресс чужих приложений на панели задач или вызывать кнопки чужих уведомлений в общем случае.
- Переназначать зарезервированные ОС сочетания (Win+L, Ctrl+Alt+Del) или перехватывать ввод в привилегированных окнах из непривилегированного процесса.
- Управлять системными «Ночным светом» и «Не беспокоить» через публичные API.

**Правила безопасности (непреложные):**
1. Никогда не делайте систему невосстановимой: поставляйте **I2 Безопасное восстановление** до любой функции, которая скрывает панель задач, ставит хук ввода или прячет окна.
2. Не заменяйте `explorer.exe` в роли оболочки Windows по умолчанию; работайте рядом и восстанавливайте всё при выходе.
3. У каждой хук-/оверлей-функции есть переключатель вкл/выкл, и она автоматически отключается в полноэкранных играх.
4. Приватность по умолчанию: без согласия нет телеметрии; содержимое нажатий клавиш и уведомлений не хранится; разрешения запрашиваются только при включении функции.

## 7. Детали функций

### A. Хром оболочки

#### A1 · Dock
*Аналог:* Dock · *Приоритет:* P0 (Phase 1 (MVP)) · *Сложность:* L · *Осуществимость:* Документированный

**Опыт.** Плавающий стеклянный pill внизу ([DESIGN.md §7.5](DESIGN.md)). Закреплённые приложения + запущенные, индикатор запуска, подъём при наведении с подсказкой, перетаскивание для порядка, бросок файла на приложение — открыть им.

**Подход на Windows.**
- Одно topmost, не активирующее окно на монитор (dock по умолчанию на основном).
- Запущенные приложения: перечислить окна верхнего уровня (EnumWindows; пропускать tool-windows, cloaked-окна через DWMWA_CLOAKED) и следить за изменениями через RegisterShellHookWindow (HSHELL_WINDOWCREATED/DESTROYED/WINDOWACTIVATED/FLASH) плюс SetWinEventHook.
- Группировать окна по идентичности приложения (AUMID для упакованных, путь exe иначе). Иконки через IShellItemImageFactory или ассеты манифеста.
- Закреплённые элементы: сохранять AUMID или путь + аргументы; при первом запуске импортировать текущие закрепления панели задач.
- Цель броска: реализовать OLE IDropTarget на каждой плитке. Меню правого клика: список окон, Keep in Dock, Options, Quit.
- Настройки: размер, положение (низ/влево/вправо), автоскрытие, эффект подъёма вкл/выкл, показывать недавние.

**Реализовано (базовый слайс).** Одна панель на основном мониторе у нижнего края экрана: стеклянный Acrylic-фон, прижата к краю и растворяется в нём — нижние углы прямые, скруглены только верхние, topmost и non-activating окно (`ShowWindow(SW_SHOWNOACTIVATE)`), поэтому клики по dock не забирают фокус. Содержимое — плитка «Пуск», закреплённые приложения и запущенные приложения с индикатором, разделённые секциями; наведение даёт непрерывную магнификацию вокруг курсора (до 12 px/1.2 под курсором, сосед ≈ 6 px/1.06) и pill-подсказку с именем. Закрепление и открепление — через контекстное меню, список сохраняется в `settings.json` (`dockPinnedApps`). Запущенные приложения вычисляются по окнам через `ApplicationProcessMatcher`, обновляются по событиям окон с коалесцированием (250 мс), а приложения вне discovery (портативные, распакованные) группируются по пути исполняемого файла. Клик по запущенному приложению переключает на его окно, повторный клик по активному — сворачивает. Настройка `dockReplacesTaskbar` (по умолчанию включена) скрывает системную панель задач: `TaskbarHider` сдвигает `Shell_TrayWnd` за край монитора, возвращает его при выходе или выключении dock и повторяет скрытие после `TaskbarCreated`/`WM_DISPLAYCHANGE`. Окно dock обрезается региональной маской с прямым нижним краем (`OverlayWindow.ApplyTopRoundedRegion`), поэтому стекло рисуется только внутри панели, а не прямоугольником вокруг неё; подъём и масштаб плиток считаются непрерывно по расстоянию до курсора (гауссов спад, до 12 px/1.2, сосед ≈ 6 px/1.06), а над плиткой появляется pill-подсказка (DESIGN §7.5). В конце ленты добавлена системная секция по DESIGN: папка «Загрузки» (`shell:Downloads`) и корзина (`shell:RecycleBinFolder`) с пастельными плитками-глифами. Не реализованы: перетаскивание плиток и импорт закреплений панели задач, бейджи, стопки папок, popover-карточка папки, «Empty» у корзины, меню окон и Quit, dock на каждый монитор, автоскрытие и резервирование рабочей области.

**Критерии готовности.**
- Реакция на наведение — в пределах 50 мс; подъём/масштаб по DESIGN.md.
- Запущенное приложение получает индикатор в пределах 500 мс; индикатор исчезает в пределах 500 мс после закрытия последнего окна.
- Закрепления, порядок и настройки переживают перезапуск.
- Работает на нескольких мониторах и при DPI 100/125/150%; никогда не перекрывает полноэкранные приложения и игры.

**Риски / заметки.** Скрытие нативной панели задач — хак (Shell_TrayWnd); она всегда должна восстанавливаться при выходе или крахе (см. I2).

#### A2 · Анимация сворачивания в dock
*Аналог:* Genie/scale minimize effect · *Приоритет:* P2 (Phase 3) · *Сложность:* M · *Осуществимость:* Частичный

**Опыт.** При сворачивании окно визуально сжимается к своей плитке dock; при восстановлении растёт обратно.

**Подход на Windows.**
- Определять сворачивание/восстановление через SetWinEventHook (EVENT_SYSTEM_MINIMIZESTART/END).
- Подменить анимацию миниатюрой DWM (DwmRegisterThumbnail) в оверлей-окне, масштабируя к плитке dock; Windows всё равно выполнит своё сворачивание.
- Уважать «уменьшить движение»: пропускать анимацию полностью.

**Критерии готовности.**
- Без мерцания и двойной анимации; мгновенный откат, если миниатюру создать не удалось.

**Риски / заметки.** Нельзя заменить нативную анимацию сворачивания чужих приложений, только замаскировать. Держать опциональным.

#### A3 · Бейджи и bounce внимания в dock
*Аналог:* Notification badges, icon bounce · *Приоритет:* P1 (Phase 2) · *Сложность:* M · *Осуществимость:* Частичный

**Опыт.** Красно-розовый бейдж-счётчик на плитке приложения при непрочитанных уведомлениях; плитка подпрыгивает дважды, когда приложение просит внимания.

**Подход на Windows.**
- Внимание: сообщение HSHELL_FLASH от shell-хука, когда окно мигает.
- Счётчики бейджей: из слушателя уведомлений (D2), сгруппированные по приложению. Сторонние приложения не могут читать overlay-бейджи панели задач других приложений.
- Стиль бейджа: pill 20px, цвет error `#FF6B81`, белый жирный 12px.

**Критерии готовности.**
- Счётчик совпадает с центром уведомлений для того же приложения.
- Bounce выполняется не более 2 раз на запрос внимания и уважает уменьшение движения.

**Риски / заметки.** Без package identity слушатель уведомлений недоступен, поэтому бейджи деградируют до «только внимание».

#### A4 · Стопки папок в dock
*Аналог:* Dock stacks (fan / grid / list) · *Приоритет:* P1 (Phase 2) · *Сложность:* M · *Осуществимость:* Документированный

**Опыт.** Папка в dock открывает popover-карточку с новыми элементами ([DESIGN.md §7.5](DESIGN.md)): сетка или список, сортировка по дате/имени/типу, кнопка «Open folder».

**Подход на Windows.**
- Миниатюры через IShellItemImageFactory; держать watcher на папке (ReadDirectoryChangesW / FileSystemWatcher).
- Перетаскивание файла на плитку папки — переместить/скопировать (Shift = переместить, Ctrl = копировать) с бейджем подтверждения.

**Критерии готовности.**
- Popover открывается менее чем за 150 мс для папок до 5000 элементов (виртуализировано).
- Клик по элементу открывает файл; Ctrl+клик показывает его в Explorer.

#### A5 · Trash
*Аналог:* Trash · *Приоритет:* P1 (Phase 2) · *Сложность:* S · *Осуществимость:* Документированный

**Опыт.** Плитка Trash в конце dock; меняет иконку при заполнении; бросок файлов удаляет; «Empty» в контекстном меню.

**Подход на Windows.**
- Состояние корзины через SHQueryRecycleBin; очистка через SHEmptyRecycleBin; удаление через IFileOperation с recycle-флагами.
- «Put back» восстанавливает исходный путь через shell-команды корзины.

**Критерии готовности.**
- Иконка «пусто/полно» обновляется в пределах 1 с после изменения.
- Подтверждение перед очисткой; размер и число элементов — в подсказке.

#### A6 · Top bar
*Аналог:* Menu bar (status items, clock) · *Приоритет:* P0 (Phase 1 (MVP)) · *Сложность:* M · *Осуществимость:* Собственный UI

**Опыт.** Три плавающих pill ([DESIGN.md §7.1](DESIGN.md)): имя приложения + расположение, строка поиска, статус + часы. Без глобального меню приложений.

**Подход на Windows.**
- Topmost-окно на монитор; резервировать рабочую область через AppBar API (SHAppBarMessage) или смещать окна вручную.
- Левый pill показывает имя foreground-приложения (из процесса foreground-окна) и, в Glaze Explorer, текущий путь.
- Правый pill размещает «меню-экстра»: Wi-Fi, громкость, батарея, часы; каждый открывает popover. Добавить размещение устаревших иконок трея в сворачиваемом переполнении.
- Клик по часам открывает popover календаря (D4).

**Критерии готовности.**
- Обновления (часы, батарея, сеть) точны в пределах 1 с.
- Не крадёт фокус при клике; доступен с клавиатуры.

**Риски / заметки.** Реальное глобальное меню для всех приложений НЕ осуществимо (см. ограничения); не обещайте его.

**Реализовано (базовый слайс).** Плавающая верхняя панель из трёх pill: имя foreground-приложения с шевроном и расположением, строка поиска (подсказка `Ctrl K`), статус (сеть, громкость, батарея) и часы с датой. Окно имеет региональную маску по границам плиток (`SetWindowRgn`), поэтому системный Acrylic-фон заполняет только три pill, а промежутки пропускают рабочий стол, — панель выглядит как три плавающих стекла, а не как одна полоса. Окно — topmost инструментальное и non-activating, не крадёт фокус (ввод поиска включается по клику или глобальной клавишей `Ctrl K`), позиционируется на основном мониторе с учётом DPI, обновляется раз в секунду; включается на странице «Верхняя панель» в настройках (`settings.json`, `topBarEnabled`). Строка поиска подключена к Glance (B1): по `Ctrl K` панель разрешает активацию, ставит фокус в поле и показывает результаты в стеклянной панели под собой, а клик мимо или `Esc` закрывает поиск. Клик по правому pill открывает popover «Центр управления» (D1) с реальной громкостью устройства вывода, выбором оформления и ссылками на системные настройки, а клик по часам — popover календаря (D4). Не реализованы: резервирование рабочей области (AppBar `SHAppBarMessage`), отдельная панель на каждый монитор и размещение иконок трея в переполнении.

#### A7 · Сетка приложений
*Аналог:* Launchpad · *Приоритет:* P1 (Phase 2) · *Сложность:* M · *Осуществимость:* Документированный

**Опыт.** Полноэкранный размытый оверлей со всеми установленными приложениями по страницам; ввод фильтрует; перетаскивание создаёт папки; Esc закрывает.

**Подход на Windows.**
- Источники: папки ярлыков меню «Пуск» плюс упакованные приложения (shell:AppsFolder / PackageManager). Запуск через IApplicationActivationManager или ShellExecute.
- Сохранять пользовательский порядок и папки; поддерживать скрытие/удаление ярлыка из контекстного меню.
- Открывать горячей клавишей, кнопкой dock или горячим углом.

**Критерии готовности.**
- Открывается менее чем за 200 мс; результаты поиска обновляются на каждое нажатие; навигация только с клавиатуры работает.

#### A8 · Колонка виджетов
*Аналог:* Notification Center widgets · *Приоритет:* P1 (Phase 2) · *Сложность:* M · *Осуществимость:* Собственный UI

**Опыт.** Правая колонка на рабочем столе ([DESIGN.md §7.6](DESIGN.md)): приветствие/часы, быстрые переключатели, системная статистика; опциональный режим редактирования для порядка и добавления виджетов.

**Подход на Windows.**
- Окно, закреплённое в нижнем z-порядке (HWND_BOTTOM, WS_EX_NOACTIVATE), чтобы лежать на обоях за приложениями; также доступно из верхней панели.
- Сначала встроенные виджеты: Часы/Приветствие, Быстрые переключатели, Система (CPU/Память/Диск), Календарь. Формат плагинов (HTML/WebView2) — решение позже.

**Критерии готовности.**
- Никогда не крадёт фокус; остаётся за обычными окнами; переживает смену мониторов.

#### A9 · Стопки и упорядочивание рабочего стола
*Аналог:* Desktop stacks, Clean Up · *Приоритет:* P2 (Phase 3) · *Сложность:* M · *Осуществимость:* Частичный

**Опыт.** Файлы рабочего стола можно группировать в стопки по типу/дате/тегу; «Clean up» расставляет иконки по сетке.

**Подход на Windows.**
- Скрыть нативный слой иконок рабочего стола (переключить вид иконок) и отрисовать папку Desktop в собственном оверлее.
- Перетаскивание между нашим оверлеем и окнами Explorer должно вести себя как нативный рабочий стол.

**Критерии готовности.**
- Выключение оверлея восстанавливает нативные иконки рабочего стола точно как было.

**Риски / заметки.** Высокий риск краевых случаев drag/drop; держать opt-in.

#### A10 · Динамические обои
*Аналог:* Dynamic desktop · *Приоритет:* P2 (Phase 3) · *Сложность:* S · *Осуществимость:* Документированный

**Опыт.** Обои следуют времени суток или светлой/тёмной теме; встроенные аврора-обои совпадают с палитрой.

**Подход на Windows.**
- Задавать обои через IDesktopWallpaper (по монитору). Планировать внутри приложения; не опрашивать чаще раза в минуту.

**Критерии готовности.**
- Пары light/dark переключаются с темой в пределах 2 с; выбор по монитору запоминается.

### B. Поиск и предпросмотр

#### B1 · Glance (глобальный поиск и лаунчер)
*Аналог:* Spotlight · *Приоритет:* P0 (Phase 1 (MVP)) · *Сложность:* L · *Осуществимость:* Документированный

**Опыт.** Глобальная горячая клавиша открывает центрированное стеклянное поле поиска. Результаты: приложения, файлы, папки, страницы настроек, вычисления, конвертации единиц/валют, команды, открытые окна, опционально история буфера, веб-fallback.

**Подход на Windows.**
- Оверлей-окно, показанное в пределах 100 мс после горячей клавиши (держать процесс «тёплым»; создать окно заранее).
- Файлы: запрос к индексу Windows Search (OLE DB-провайдер SystemIndex или ISearchQueryHelper); опционально собственный индекс для добавленных пользователем папок. Приложения: меню «Пуск» + упакованные. Настройки: URI `ms-settings:`.
- Калькулятор и конвертации: безопасный парсер выражений (никогда не eval); курсы валют кэшируются, обновляются в фоне, явно помечаются как приблизительные.
- Команды (префикс `>`): блокировка, сон, перезагрузка, переключить тёмную тему, очистить корзину, восстановить UI Windows и т.д.
- Ранжирование: точный префикс > частота/недавность > нечёткое совпадение; учиться на выборах локально.
- Клавиатура: стрелки, Enter открывает, Ctrl+Enter показывает в Explorer, Tab — предпросмотр (B2), Alt+1…9 — быстрый выбор, Esc закрывает.

**Критерии готовности.**
- Первый результат виден менее чем за 150 мс для типичных запросов; ввод никогда не блокируется (async + отмена).
- Работает полностью офлайн, кроме валют/веба.
- Уважает исключённые папки и «приватный режим», отключающий результаты из буфера.

**Риски / заметки.** Горячая клавиша по умолчанию требует проверки конфликтов (см. §5). Доступность индекса различается; показывать ясное сообщение, если Windows Search отключён.

**Реализовано (базовый слайс).** Глобальная горячая клавиша `Ctrl K` (`GlobalHotkey` в `GlazeShell.Windows`: отдельный поток с невидимым окном и петлёй сообщений, `RegisterHotKey`) разрешает активацию верхней панели и ставит фокус в строку поиска, даже когда Glaze Shell не в фокусе; если комбинацию заняла другая программа, приложение работает без неё и пишет предупреждение в лог. Ранжирование вынесено в framework-free ядро `GlazeShell.Core/Glance` (`GlanceRanker`: точное совпадение > префикс > начало слова > вхождение > пояснение > ключевые слова, все слова запроса должны совпасть) и покрыто тестами. Источник кандидатов — `Presentation/GlanceSearchCatalog`: приложения (ленивое сканирование `IApplicationManager.DiscoverAsync` с кэшем), открытые окна (свежий снимок `IWindowManager.GetWindows`, свои окна исключены), страницы системных настроек (`ms-settings:`) и команды Glaze Shell. Результаты показываются в стеклянной панели под строкой поиска в том же acrylic-окне (без отдельного popup, чтобы не терять фокус): стрелки двигают выбор, `Enter` открывает, `Esc` или клик мимо закрывают. Приложения запускаются через `IApplicationLauncher`, окна переключаются `IWindowManager.FocusWindow`, настройки открываются по URI, команды выполняет слой приложения. Не реализованы: поиск по файлам (индекс Windows Search: OLE DB SystemIndex или `ISearchQueryHelper`), калькулятор и конвертации, история буфера, веб-fallback, обучение на выборах (частота/недавность), `Ctrl+Enter` (показать в Explorer), `Tab`-предпросмотр (B2), `Alt+1…9`, префикс `>` для команд и «приватный режим».

#### B2 · Quick Preview
*Аналог:* Quick Look (Space) · *Приоритет:* P0 (Phase 1 (MVP)) · *Сложность:* M · *Осуществимость:* Частичный

**Опыт.** Нажатие пробела на выбранном файле — крупный плавающий предпросмотр; стрелки двигают по выборке; пробел/Esc закрывает.

**Подход на Windows.**
- В Glaze Explorer: нативно. В Windows File Explorer: читать текущее выделение через shell-интерфейсы автоматизации (IShellWindows → IFolderView2), пока фокус в окне Explorer, и только если пользователь это включил.
- Рендеринг: зарегистрированные обработчики предпросмотра (IPreviewHandler) для Office/PDF и т.п., плюс встроенные рендереры для изображений, видео/аудио, текста/кода, Markdown, архивов (листинг), папок (сводка).
- Окно: стеклянная карточка, радиус 32, заголовок с именем файла, кнопка «Open with», зум, поделиться/копировать путь.

**Критерии готовности.**
- Предпросмотр появляется менее чем за 250 мс для типичных изображений/PDF/текста; поддерживает минимум изображения, PDF, текст/код, видео, аудио.
- Никогда не блокирует файл (открывает на чтение с общим доступом) и не выполняет содержимое.

**Реализовано (базовый слайс).** Пробел на выбранном элементе проводника (или кнопка «Предпросмотр» в тулбаре) открывает карточку предпросмотра (`PreviewWindow` + `PreviewViewModel`): имя файла, вид/размер/дата, содержимое и нижняя строка с полным путём, кнопками «Открыть» (приложение по умолчанию) и «Копировать путь». Виды показа: **картинки** (png/jpg/gif/bmp/webp/svg/heic и др. декодирует WinUI, файл крупнее 512 МБ не рисуется, битый файл деградирует до глифа), **текст и код** (txt/log/md/json/xml/yml/csv, cs/py/js/ts/html/css/ps1/sh и др.; чтение в фоне через `IFilePreviewReader`, распознавание UTF-8/UTF-16 по BOM, отсечение «двоичного» файла с нулями, ограничение 256 КБ/120 000 символов с пометкой об обрезке, выделение текста мышью), **сводка папки** (число элементов с ограничением 10 000) и **метаданные для прочего** (аудио/видео/архив/неизвестное — глиф, размер, дата и «Открыть»). Файл открывается на чтение с `FileShare.ReadWrite|Delete` — предпросмотр не блокирует его у другого приложения; содержимое не выполняется. Карточка закрывается по `Esc`, пробелу или кнопке, в системе живёт не более одной, и она закрывается вместе с проводником. Не реализованы: предпросмотр PDF/Office через `IPreviewHandler`, видео/аудио проигрывателем, зум картинки, «Открыть с помощью» (`SHOpenWithDialog`), движение по выборке стрелками, предпросмотр в стандартном File Explorer (`IShellWindows`/`IFolderView2`) и `Tab`-предпросмотр из Glance.

**Риски / заметки.** Чтение выделения из стандартного File Explorer хрупко между сборками Windows; считать best-effort. PowerToys Peek — полезный ориентир по UX, но не зависимость.

### C. Окна и рабочие пространства

#### C1 · Overview
*Аналог:* Mission Control · *Приоритет:* P1 (Phase 2) · *Сложность:* L · *Осуществимость:* Частичный

**Опыт.** Один жест/горячая клавиша показывает все окна живыми миниатюрами, сгруппированными по workspace, с полосой workspaces сверху; клик фокусирует, наведение показывает кнопку закрытия.

**Подход на Windows.**
- Миниатюры через DwmRegisterThumbnail (живые) в адаптивной сетке; отфильтровать cloaked/невидимые окна.
- Триггер: горячая клавиша, горячий угол, кнопка dock. Анимация 220 мс со стандартной кривой; уменьшение движения = мгновенно.

**Критерии готовности.**
- Открывается менее чем за 150 мс с 20 окнами; фокус на окне восстанавливает его из свёрнутого; Esc возвращает без изменений.

**Риски / заметки.** Миниатюры защищённых/привилегированных окон могут рисоваться чёрными; показывать иконку вместо них.

#### C2 · Workspaces
*Аналог:* Spaces / multiple desktops · *Приоритет:* P1 (Phase 2) · *Сложность:* L · *Осуществимость:* Собственный UI

**Опыт.** Несколько именованных рабочих пространств; переключение сочетаниями или полосой Overview; перенос окон между ними; опционально обои на workspace.

**Подход на Windows.**
- РЕКОМЕНДУЕТСЯ: реализовать собственные workspaces — переключение прячет окна других workspace (ShowWindow/cloak-скрытие) и показывает целевой набор; держать карту HWND → workspace и восстанавливать всё при выходе.
- Виртуальные рабочие столы Windows: IVirtualDesktopManager документирован, но отвечает лишь «на каком рабочем столе это окно» и перемещает окно; создание/удаление/переключение требует недокументированных COM-интерфейсов, меняющихся между сборками. Интеграцию считать опциональной и хрупкой.

**Критерии готовности.**
- Переключение 10 окон занимает менее 200 мс и не теряет фокус в целевом workspace.
- Закрытие Glaze Shell (или крах) никогда не оставляет окна скрытыми: сторож (I2) восстанавливает их.

**Риски / заметки.** Нужно продуктовое решение: свои workspaces против нативных виртуальных рабочих столов (см. §9).

#### C3 · Snap и тайлинг
*Аналог:* Window tiling (Sequoia и позже) · *Приоритет:* P1 (Phase 2) · *Сложность:* M · *Осуществимость:* Документированный

**Опыт.** Перетащить окно к краю/углу или нажать сочетание, чтобы затайлить: половины, трети, четверти, сетка, свои зоны; предпросмотр в стиле Glaze показывает цель.

**Подход на Windows.**
- Определять перетаскивание через SetWinEventHook (EVENT_SYSTEM_MOVESIZESTART/END) + позиция курсора; размещать через SetWindowPos по рабочей области монитора.
- Компенсировать невидимые границы изменения размера через DWMWA_EXTENDED_FRAME_BOUNDS, чтобы тайлы совпадали пиксель-в-пиксель.
- Опции: размер gap, радиус углов предпросмотра, память по приложению, сочетания для каждой раскладки.
- Сосуществовать с Snap Layouts Windows 11 (не отключать их; избегать двойной обработки, проверяя состояние окна).

**Критерии готовности.**
- Раскладки применяются в пределах 100 мс; корректны на нескольких мониторах и смешанном DPI; сочетание undo возвращает прежние границы.

#### C4 · Переключатель приложений
*Аналог:* Cmd+Tab app switcher · *Приоритет:* P1 (Phase 2) · *Сложность:* M · *Осуществимость:* Частичный

**Опыт.** Удерживая модификатор, Tab перебирает приложения (одна иконка на приложение, не на окно); вторая клавиша перебирает окна одного приложения; Q выходит из подсвеченного, H скрывает его.

**Подход на Windows.**
- Низкоуровневый хук клавиатуры (WH_KEYBOARD_LL) для перехвата Alt+Tab; оверлей показывает плитки из модели dock.
- Quit = послать WM_CLOSE окнам приложения и предложить «Force quit» после таймаута; никогда не убивать молча.
- Хук без прав администратора не видит нажатия, отправленные привилегированным окнам (UIPI); в этом случае откатываться к системному переключателю.

**Критерии готовности.**
- Переключатель появляется в пределах 100 мс после первого Tab; отпускание модификатора фокусирует выбранное приложение.

**Риски / заметки.** Хуки клавиатуры могут вызывать эвристики антивирусов; подписывать приложение и документировать разрешение.

#### C5 · Горячие углы
*Аналог:* Hot Corners · *Приоритет:* P2 (Phase 3) · *Сложность:* S · *Осуществимость:* Документированный

**Опыт.** Наведение указателя в угол экрана запускает настраиваемое действие: Overview, сетка приложений, показать стол, блокировка, скриншот, ничего.

**Подход на Windows.**
- Хук мыши или лёгкий опрос курсора с задержкой 300 мс и небольшой мёртвой зоной.
- Отключать при активном полноэкранном приложении/игре (проверять SHQueryUserNotificationState).

**Критерии готовности.**
- Нет случайных срабатываний при обычной работе (задержка + мёртвая зона); действие на угол и опция клавиши-модификатора.

#### C6 · Скрыть / скрыть остальные / показать стол
*Аналог:* Cmd+H, Cmd+Opt+H · *Приоритет:* P2 (Phase 3) · *Сложность:* S · *Осуществимость:* Документированный

**Опыт.** Скрыть все окна приложения, скрыть всё кроме текущего приложения или подсмотреть рабочий стол.

**Подход на Windows.**
- ShowWindow per window (запоминать состояние для восстановления); показать стол — через собственную логику оверлея, а не сворачивая всё.

**Критерии готовности.**

### D. Управление и уведомления

#### D1 · Панель Quick Settings
*Аналог:* Control Center · *Приоритет:* P0 (Phase 1 (MVP)) · *Сложность:* M · *Осуществимость:* Частичный

**Опыт.** Стеклянный popover из верхней панели с переключателями (Wi-Fi, Bluetooth, Ночь, Фокус, Тёмная тема, Авиарежим) и слайдерами (громкость, яркость); также встроен в колонку виджетов ([DESIGN.md §7.6](DESIGN.md)).

**Подход на Windows.**
- Радио (Wi-Fi/Bluetooth/Авиарежим): Windows.Devices.Radios (WinRT); нужно разрешение пользователя на доступ к радио.
- Громкость: Core Audio (IAudioEndpointVolume); выбор устройства вывода через энумератор эндпоинтов (у переключения устройства по умолчанию нет публичного API; считать хрупким).
- Яркость: встроенные панели через WMI (WmiMonitorBrightnessMethods); внешние мониторы через DDC/CI (функции яркости Dxva2).
- Тёмная тема: писать AppsUseLightTheme / SystemUsesLightTheme и рассылать WM_SETTINGCHANGE («ImmersiveColorSet»).
- Ночной свет: публичного API для системной функции нет. Реализовать собственный тёплый оверлей (например, цветовой эффект Magnification API) вместо ковыряния недокументированных бинарных ключей реестра.
- Фокус/Do Not Disturb: публичного API нет; использовать собственный DND (D3), управляющий нашим UI уведомлений.

**Критерии готовности.**
- Каждый переключатель показывает реальное состояние при открытии и обновляется при изменении извне.
- Слайдеры применяются вживую без лагов (троттлинг до 30 Гц).
- Недоступное железо (нет Bluetooth, нет управления яркостью) скрывает или отключает элемент с короткой причиной.

**Риски / заметки.** Точная доступность и поведение API меняются между сборками Windows; проверяйте по актуальной документации Microsoft перед реализацией каждого элемента.

**Реализовано (базовый слайс).** Стеклянный popover «Центр управления» открывается кликом по правому pill верхней панели и живёт в том же окне, что и Glance: окно на время показа разрешает активацию (в popover есть элементы управления), а клик мимо закрывает его по «light dismiss»; поиск и popover не показываются одновременно. В popover: **реальная громкость устройства вывода по умолчанию через Core Audio** (`IAudioEndpointVolume`: ползунок уровня 0–100 и кнопка «без звука» с глифом состояния), **режим оформления Glaze Shell** (тот же выбор, что и в главном окне, включая «Тёмную») и **быстрые ссылки** на страницы настроек Windows (`ms-settings:network`, `ms-settings:bluetooth`, `ms-settings:sound`). Громкость читается и применяется с устройства по умолчанию; ссылка на устройство переживает его смену (при первой ошибке перечитывается), а при отсутствии устройства вывода ползунок и кнопка отключаются с пояснением «Устройство вывода не найдено». Данные о громкости обновляются раз в секунду, пока popover открыт, поэтому изменения клавишами мультимедиа и системным микшером видны в интерфейсе. Не реализованы: переключатели Wi-Fi/Bluetooth/авиарежима (`Windows.Devices.Radios` требует разрешения на доступ к радио, которое Win32-приложению без упаковки Windows не выдаёт), яркость (WMI для встроенных панелей и DDC/CI для внешних — следующий шаг), «Ночной свет» (публичного API нет) и «Фокус» (D3). «Тёмная тема» управляет оформлением самого Glaze Shell, а не системной темой Windows: движок оформления проекта не меняет системные настройки.

#### D2 · Центр уведомлений
*Аналог:* Notification Center · *Приоритет:* P1 (Phase 2) · *Сложность:* L · *Осуществимость:* Частичный

**Опыт.** Уведомления, сгруппированные по приложению, новые сверху, с очисткой всех, очисткой по приложению, отложить и переходом по клику.

**Подход на Windows.**
- Читать уведомления через WinRT API UserNotificationListener. Требует, чтобы пользователь дал разрешение, и, по документации Microsoft и отчётам сообщества, package identity (MSIX или sparse/external-location package) — планировать упаковку соответственно.
- В общем случае нельзя вызывать кнопки чужих toast-уведомлений; клик открывает приложение. Нативные тосты Windows всё равно появляются, пока пользователь не отключит баннеры или не включит Фокус; предложить пошаговую настройку, а не взламывать их.
- Хранить только метаданные, нужные для вида; никогда не логировать текст сообщения; очищать по запросу.

**Критерии готовности.**
- Новые уведомления появляются в панели в пределах 1 с; группировка и счётчики совпадают с бейджами (A3).
- Работает только после явного разрешения; ясное объяснение при отказе.

**Риски / заметки.** Выбор упаковки (installer против MSIX/external location) напрямую влияет на эту функцию (см. §9).

#### D3 · Режимы фокуса
*Аналог:* Focus · *Приоритет:* P2 (Phase 3) · *Сложность:* M · *Осуществимость:* Собственный UI

**Опыт.** Именованные режимы (Работа, Личное, Сон) с разрешёнными приложениями, расписаниями и иконкой в верхней панели.

**Подход на Windows.**

**Критерии готовности.**

#### D4 · Popover часов и календаря
*Аналог:* Clock menu / Calendar · *Приоритет:* P1 (Phase 2) · *Сложность:* S · *Осуществимость:* Собственный UI

**Опыт.** Сетка месяца, выделение сегодня, опционально номера недель, предстоящие события при подключённом источнике календаря.

**Подход на Windows.**
- События опциональны: ICS-URL или коннектор аккаунта позже; сетка сама по себе должна работать офлайн.

**Критерии готовности.**
- Первый день недели и форматы чисел — с учётом локали.

**Реализовано (базовый слайс).** Часы в правом pill верхней панели стали кнопкой и открывают стеклянный popover календаря в том же acrylic-окне (отдельный слой под pill, ширина 380, радиус 32 — как у «Центра управления»); Glance, «Центр управления» и календарь взаимоисключающие. Логика сетки вынесена в framework-free ядро `Core/Calendar/`: `CalendarDay` (дата, признаки «сегодня», выходного и текущего месяца) и `MonthCalendar` (всегда 6 недель × 7 дней, первый день недели передаётся из `CultureInfo.CurrentCulture.DateTimeFormat.FirstDayOfWeek`, `Shift` листает месяцы, `ShowsMonthOf` определяет заголовок), покрыта юнит-тестами. `Presentation/CalendarViewModel` сбрасывается на текущий месяц при каждом открытии, форматирует название месяца и года по культуре и управляет доступностью кнопки «Сегодня»; `CalendarDayViewModel` и `CalendarWeekViewModel` готовят ячейки для биндинга и озвучиваемые имена `AutomationProperties.Name` (включая пометку «сегодня»). В `TopBarWindow` — заголовок с кнопками «‹»/«›»/«Сегодня», названия дней недели по культуре и шесть строк недель; сегодняшний день обведён акцентным кольцом, дни соседних месяцев приглушены. Popover закрывается по `Esc`, повторному клику по часам и клику мимо; клик по часам больше не открывает быстрые настройки. Не реализованы: список событий и задач (ICS или коннектор календаря), недельный и дневной вид, выбор месяца и года из заголовка, номера недель, несколько календарей и праздники.

#### I2 · Безопасное восстановление и сторож
*Аналог:* Safe Mode / recovery · *Приоритет:* P0 (Phase 1 (MVP)) · *Сложность:* S · *Осуществимость:* Документированный

**Опыт.** Гарантированный путь назад: команда из трея и горячая клавиша «Восстановить UI Windows», CLI-флаг и автоматическое восстановление после повторных крахов.

**Подход на Windows.**
- Крошечный отдельный процесс-сторож восстанавливает нативную панель задач, иконки рабочего стола, скрытые/cloaked-окна и снимает хуки, если оболочка завершилась неожиданно.
- Безопасный режим стартует со всеми отключёнными хуками/оверлеями; авто-вход после 3 крахов за 5 минут.
- Горячая клавиша восстановления должна быть редко используемой и настраиваемой.

**Критерии готовности.**
- Убийство главного процесса из Task Manager восстанавливает работоспособный рабочий стол в пределах 3 с.

**Риски / заметки.** Это самая важная функция для доверия пользователей; тестируйте её до отгрузки всего, что хукает систему.

**Реализовано (базовый слайс).** Правила восстановления вынесены в framework-free ядро — `Core/Recovery/`: `CrashTracker` (окно падений и правило «3 падения за 5 минут»), `StartupMode`/`StartupModeResolver` (выбор обычного или безопасного режима с объяснением причины), `RecoveryHotkey` (редкая комбинация клавиш: только `F1`–`F12` и не менее трёх модификаторов, по умолчанию `Ctrl+Alt+Shift+F12`) и `RecoveryCommandLine` (разбор `--safe-mode`, `--restore-ui`, `--watchdog <pid>`). Обнаружение падения — по состоянию сессии: `Data/Recovery/RecoveryStore.cs` хранит `recovery.json` в корне пользовательских данных, при запуске сессия помечается незавершённой, при штатном выходе — завершённой, поэтому незавершённая прошлая сессия означает падение, а не перезапуск. Счётчик падений живёт в том же документе; три падения за пять минут (или ключ `--safe-mode`, или переключатель в настройках) включают безопасный режим: системные источники событий не стартуют, dock и верхняя панель не создаются, системная панель задач не скрывается — оболочка ничего не меняет в системе, но главное окно открывается, чтобы пользователь мог выйти из режима. Сторож работает отдельным процессом: `Windows/Lifecycle/WatchdogLauncher.cs` запускает тот же исполняемый файл с ключом `--watchdog <pid>`, а `ProcessExitWatcher` опрашивает процесс каждые 200 мс (сверяя момент запуска, чтобы не принять переиспользованный идентификатор за тот же процесс) и после его завершения возвращает интерфейс — критерий «рабочий стол за 3 с» выполняется с запасом, восстановление занимает около секунды. Само восстановление — `Windows/Shell/WindowsUiRestorer.cs`: системная панель задач возвращается на место (`TaskbarHider.RestoreIfOffScreen`), окно значков рабочего стола (`SHELLDLL_DefView` внутри `Progman` или `WorkerW`) показывается и возвращается на экран, если оказалось за границей монитора. Три способа запустить восстановление: редкая клавиша `Ctrl+Alt+Shift+F12` (регистрируется всегда, пока она включена в настройках, и предупреждает в лог, если комбинацию заняла другая программа), кнопка «Восстановить UI» в шапке главного окна и ключ `--restore-ui` (возвращает интерфейс, показывает системное сообщение и завершает работу). Настройки живут на новой странице «Восстановление» каталога (`recoveryHotkeyEnabled`, `recoveryHotkeyId`, `safeModeEnabled`) и сохраняются в `settings.json`. Не реализованы: команда из трея (значка трея в проекте нет, поэтому команда вынесена в главное окно), восстановление скрытых и cloaked-окон чужих приложений (Glaze Shell чужие окна не скрывает), отдельный крошечный исполняемый файл сторожа (сторож — тот же файл в отдельном процессе без создания окон), показ баннера безопасного режима в интерфейсе (сейчас есть только запись в журнале) и ручной сброс счётчика падений.

#### I5 · Доступность
*Аналог:* Accessibility · *Приоритет:* P0 (Phase 1 (MVP)) · *Сложность:* M · *Осуществимость:* Документированный

**Опыт.** Всё доступно с клавиатуры, озвучивается Narrator, читаемо при высокой контрастности и спокойно для тех, кто не любит движение.

**Подход на Windows.**
- Имена/роли UI Automation для всех собственных контролов; видимый фокус-ринг (2px accent + 2px offset).
- Уважать темы высокой контрастности Windows (отключать стекло, использовать системные цвета) и «уменьшить анимации».

**Критерии готовности.**
- Проходит обход Narrator по dock, верхней панели, Glance и Explorer; проверки контраста по [DESIGN.md §3](DESIGN.md).

**Реализовано (базовый слайс).** Правила доступности вынесены в framework-free ядро: `Core/Services/AccessibilityResolver.cs` складывает системные возможности Windows и настройки пользователя в `AccessibilityState` (`ReduceMotion`, `HighContrast`), причём системные ограничения сильнее пользовательских — выключенные в Windows анимации и включённая контрастность остаются в силе, даже если пользователь их не просил. Системные факты читает `Windows/SystemAccessibility/SystemAccessibilityProvider.cs` через Win32: `SPI_GETCLIENTAREAANIMATION` (разрешены ли анимации), `SPI_GETHIGHCONTRAST` (тема высокой контрастности) и `GetSysColor` (палитра: фон, текст, выделение, приглушённый текст) — без WinRT `UISettings`/`AccessibilitySettings`, потому что их API требует Windows 10 19041, а минимум проекта — 1809. Настройки пользователя живут рядом с остальными: `UserSettings.ReduceMotion` и `UserSettings.HighContrast` сохраняются в `settings.json` (`reduceMotion`, `highContrast`) и вынесены на отдельную страницу «Доступность» каталога настроек. Визуальная часть сосредоточена в `Theming/ThemeApplicator`: он единственный владелец токен-кистей, поэтому в контрастном режиме приглушённые оттенки заменяются системной палитрой, стекло становится непрозрачным (`Backdrop` отключается в dock и верхней панели), а брендовый градиент — сплошным системным выделением; решение о светлой или тёмной теме в контрастном режиме принимает система (`RequestedTheme = Default`). Видимый фокус-ринг — 2 px акцентом с отступом: глобальные `FocusVisualPrimaryBrush`/`FocusVisualSecondaryBrush` дают его встроенным контролам, а у плиток dock, где `FocusVisual` недоступен на `Border`, ринг рисуется вручную (`GotFocus`/`LostFocus` у плитки). Клавиатурный доступ и озвучивание: у всех иконочных кнопок, переключателей, полей и элементов списков заданы `AutomationProperties.Name` (например, «Назад», «Вперёд», «На уровень выше», «Обновить», «Предпросмотр выбранного элемента», «Поиск Glance», «Центр управления», «Закрыть предпросмотр», «Копировать путь в буфер обмена») и `AutomationId`, а статусный pill верхней панели стал `IsTabStop` с обработкой `Enter`/`Space`. Не реализованы: полный обход Narrator (роли и состояния у собственных шаблонов), озвучивание результатов Glance, `AutomationPeer` для плиток dock, настройки масштаба текста и альтернативные тексты для иконок.

#### I6 · Мультимонитор, DPI и производительность
*Аналог:* — · *Приоритет:* P0 (Phase 1 (MVP)) · *Сложность:* M · *Осуществимость:* Документированный

**Опыт.** Хорошо ведёт себя на нескольких мониторах со смешанным масштабированием и остаётся лёгким в фоне.

**Подход на Windows.**
- Per-monitor DPI awareness v2; настройки dock/верхней панели по монитору.
- Бюджеты (предлагаемые): idle CPU < 1%, idle память < 200 МБ, открытие Glance < 100 мс, без просадок кадров в анимациях на встроенных GPU.

**Критерии готовности.**
- Горячее подключение монитора перекладывает оболочку без перезапуска.

**Реализовано (базовый слайс).** Правила размещения панелей вынесены в framework-free ядро: `Core/Display/ShellPlacement.cs` (`ShellAnchor` — верх/низ, `ShellAlignment` — центр/лево/право/во всю ширину, `ShellPlacement` — прямоугольник в пикселях) и `Core/Display/ShellPlacementResolver.cs`. Размещение — чистая функция от монитора, якоря, выравнивания и размера панели, поэтому одинаковое правило применяется и к dock, и к верхней панели и проверяется юнит-тестами (`ShellPlacementResolverTests`): панель задаётся в логических единицах (DIP), а результат возвращается в физических пикселях, потому что `AppWindow.MoveAndResize` принимает пиксели, а у соседних мониторов может быть разный масштаб (DPI/96). Целевой монитор выбирается по правилу, а не по текущему фокусу: сначала системный основной монитор, при его отсутствии — первый подключённый, поэтому панели не уезжают при каждом переключении между приложениями; правило — `ShellPlacementResolver.SelectTarget`, кэш и перечитывание — `App/Presentation/ShellMonitorTarget.cs` (мониторы перечисляются один раз, а не при каждой перерисовке панели). Реакция на смену конфигурации дисплеев событийная: `MonitorManager` коалесцирует `WM_DISPLAYCHANGE`/`WM_DEVICECHANGE`/`WM_SETTINGCHANGE` и публикует `DisplayChanged`, а dock и верхняя панель подписаны на него и перекладываются на новый монитор без перезапуска оболочки (перерисовка — в UI-потоке через `DispatcherQueue.TryEnqueue`, потому что публикация идёт из потока системных событий). Верхняя панель переносится по полному прямоугольнику, а не только по высоте: раньше окно двигалось только при изменении высоты, поэтому при смене монитора панель оставалась на старом экране. Бюджеты производительности — тоже framework-free: `Core/Diagnostics/PerformanceBudget.cs` (`PerformanceBudget`, `PerformanceBudgets.Default`, `PerformanceMeasurement`, `PerformanceBudgetEvaluator`) с значениями из карты функций (idle CPU < 1 %, idle-память < 200 МБ, открытие Glance < 100 мс); бюджет, который не измерялся (например, Glance ни разу не открывался), не считается нарушенным и просто не попадает в отчёт. Вердикт по бюджетам пишется в журнал при закрытии оболочки: в пределах бюджета — обычной записью, за пределами — предупреждением. Не реализовано (следующие шаги): выбор монитора панелей вручную (панели следуют за системным основным монитором), замер времени открытия Glance (в отчёт не попадает), настройка места панелей на экране, троттлинг фоновой работы и профилирование кадров анимаций на встроенных GPU.

## 8. Сквозные требования

- **Дизайн:** весь UI следует [DESIGN.md](DESIGN.md) и `design/tokens/`; обе темы; никаких вшитых цветов.
- **Доступность:** см. I5; клавиатурный путь для каждого действия; метки Narrator; уменьшение движения; откат к высокой контрастности.
- **Производительность:** см. бюджеты I6; анимации должны оставаться плавными на встроенных GPU; фоновая работа троттлится.
- **Надёжность:** каждый хук, оверлей и скрытое окно регистрируются в одном месте, чтобы сторож (I2) мог всё откатить.
- **Приватность и безопасность:** разрешения запрашиваются just-in-time с объяснением простым языком; данные только локально; подписанные бинарники; никаких сетевых вызовов без видимой настройки.
- **Локализация:** все строки вынесены; минимум русский и английский; даты и числа с учётом локали.
- **Телеметрия:** off по умолчанию; если добавят позже — opt-in с видимым журналом отправляемого.
- **Тестирование:** юнит-тесты для логики (ранжирование, парсинг, раскладки), интеграционные тесты для хуков с тестовым харнессом, ручные чек-листы для безопасного восстановления, мультимонитора, DPI 100/125/150%, Windows 11 (основная) и Windows 10 (degraded).
